# データガバナンス

## 概要

データガバナンスは、組織全体でデータを適切に管理・活用するための体系です。プライバシー保護、データ品質管理、メタデータ管理、データリネージ追跡を通じて、信頼性の高いデータ資産を構築します。

---

## プライバシー・セキュリティ

**個人情報保護法 (APPI)** は、日本における個人情報の取扱いを規定する法律です。本人同意、利用目的の明示、安全管理措置が必須です。

**Privacy by Design** は、システム設計の初期段階からプライバシーを組み込む考え方です。後付けではなく、要件定義から実装まで一貫してプライバシーを考慮します。

**オプトイン/オプトアウト:**
- **オプトイン：** 明示的な同意が必要（より厳密）
- **オプトアウト：** デフォルトで利用され、拒否可能（緩和的）

**実装例：**
```javascript
// プライバシーポリシーへの同意チェック
async function registerUser(email, agreeToPolicy) {
  if (!agreeToPolicy) {
    throw new Error('Privacy policy acceptance is required');
  }

  await db.users.create({
    email,
    consentedAt: new Date(),
    privacyVersion: '1.0'
  });
}
```

## 個人情報 (PII) の保護

**PIIの種別：** 氏名、メールアドレス、電話番号、住所、社会保障番号など、個人を特定できる情報。

**匿名化技術：**
- **ハッシュ化：** 一方向変換。復号不可だが、レインボーテーブル攻撃のリスク
- **暗号化：** 可逆変換。鍵管理が必要
- **トークン化：** 本物のデータを代替文字列に置き換え

```javascript
// ハッシュ化の実装
const crypto = require('crypto');

function hashEmail(email) {
  return crypto.createHash('sha256').update(email).digest('hex');
}

// 動的マスキング
function maskEmail(email) {
  const [local, domain] = email.split('@');
  const masked = local.substring(0, 2) + '*'.repeat(local.length - 2);
  return `${masked}@${domain}`;
}

console.log(maskEmail('john.doe@example.com'));  // jo*****@example.com
```

## マスターデータ管理

**マスターデータの定義：** 組織全体で共有すべき基本データ（顧客情報、商品情報、部門情報など）

**Single Source of Truth (SSOT)：** マスターデータは1つの信頼できるソースから供給され、すべてのシステムはこれを参照します。

**名寄せ（Data Matching）：** 複数のシステムから得た同一顧客データを統合し、重複排除する処理。

```javascript
// 名寄せロジックの例
function matchCustomers(customer1, customer2) {
  const nameMatch = levenshteinDistance(customer1.name, customer2.name) < 3;
  const emailMatch = customer1.email === customer2.email;
  const phoneMatch = customer1.phone === customer2.phone;

  return nameMatch && (emailMatch || phoneMatch);
}

// 統合マスターテーブルの設計
const masterCustomer = {
  masterId: 'CUST-001',
  name: 'John Doe',
  email: 'john@example.com',
  phone: '090-xxxx-xxxx',
  sources: ['system_A', 'system_B'],  // 参照元追跡
  lastUpdated: '2024-01-15T10:30:00Z'
};
```

## メタデータ管理

**メタデータの種類：**
- **技術メタデータ：** スキーマ、データ型、更新頻度
- **業務メタデータ：** データの説明、所有者、利用目的
- **処理メタデータ：** ETL/ジョブの定義、変換ルール

**データディクショナリ：** すべてのデータ項目の説明・定義を集約したドキュメント

**カタログツール：** Collibra、Alation などのツールでメタデータを一元管理

## データ品質管理

**データ品質の6つの次元:**
1. **正確性 (Accuracy)：** データが実世界を正確に表現
2. **完全性 (Completeness)：** 必要なデータがすべて存在
3. **一貫性 (Consistency)：** システム間でデータが矛盾しない
4. **適時性 (Timeliness)：** データが最新
5. **一意性 (Uniqueness)：** 重複がない
6. **妥当性 (Validity)：** ドメイン制約を満たす

**データ品質テストの実装:**
```python
import pandas as pd

def validate_data_quality(df):
  issues = []

  # 完全性チェック
  missing = df.isnull().sum()
  if missing.any():
    issues.append(f'Missing values: {missing[missing > 0].to_dict()}')

  # 妥当性チェック
  if (df['age'] < 0).any() or (df['age'] > 150).any():
    issues.append('Age out of valid range')

  # 一意性チェック
  duplicates = df.duplicated(subset=['email']).sum()
  if duplicates > 0:
    issues.append(f'{duplicates} duplicate emails')

  return issues
```

## データリネージと影響分析

**リネージの定義と目的：** データの出所、変換プロセス、流れを追跡。障害時の影響範囲特定やコンプライアンス対応に活用

**アップストリームとダウンストリーム：**
- **アップストリーム：** データの出所（ソースシステム）
- **ダウンストリーム：** データの利用先（ダッシュボード、レポート）

```javascript
// リネージ図の例構造
const dataLineage = {
  source: 'CRM_System',
  process: 'customer_etl',
  transformations: [
    { name: 'normalize_email', description: '小文字に統一' },
    { name: 'dedup_by_email', description 'メールで重複排除' }
  ],
  targets: ['data_warehouse', 'analytics_db'],
  lastUpdated: '2024-01-20'
};
```

**自動収集の仕組み：** データベースクエリログ、ETLジョブログから自動的にリネージを抽出

## ガバナンス体制

**ガバナンスの役割定義：**
- **Data Steward：** 業務側の代表。データ品質・利用ルールを定義
- **Data Owner：** IT側の責任者。インフラ・セキュリティを担当
- **Data Custodian：** 日次の運用担当

**RACIチャート：** 各ロールの責任（Responsible）、説明責任（Accountable）、相談対象（Consulted）、情報提供（Informed）を明確化

---

## ベストプラクティス

- **段階的導入：** 重要度の高いデータから管理開始
- **自動化：** データプロファイリング、品質チェックの自動化
- **監視・レポート：** 品質KPIを定期報告
- **教育・啓発：** データリテラシー向上のための組織的取り組み
