# AZ. NoSQL・その他データストア

## 概要

NoSQLデータベースは、柔軟なスキーマ、水平スケーラビリティ、特定のアクセスパターン最適化を提供します。リレーショナルDBでは困難な超大規模データの処理や高速検索に対応できます。このセクションでは、NoSQL選定、全文検索、データモデリングの最適化を学習します。

---

## データストアの選定基準

**CAP定理** は、分散システムにおいて3つの特性（一貫性、可用性、分割耐性）のうち、同時に2つまでしか満たせないという原則です。

- **Consistency （一貫性）：** すべてのクライアントが同じデータを参照
- **Availability （可用性）：** システムが常に応答可能
- **Partition tolerance （分割耐性）：** ネットワーク分割時も動作

**Polyglot Persistence** は、用途に応じて複数のデータベースを使い分けるアプローチです。

**データストア選定:**
- **トランザクション重視：** PostgreSQL（関係型DB）
- **キャッシュ・セッション：** Redis（キー・バリュー）
- **ドキュメント：** MongoDB（ドキュメント型）
- **全文検索：** Elasticsearch（検索特化）
- **グラフデータ：** Neo4j（グラフ型）
- **時系列：** InfluxDB（時系列DB）

## NoSQLの非正規化設計

リレーショナルDBでは正規化が重要ですが、NoSQLでは非正規化により読み取り性能を優先します。

**アクセスパターン設計:**
```javascript
// ❌ 正規化（複数クエリが必要）
db.users.findOne({ id: 1 });
db.posts.find({ userId: 1 });

// ✅ 非正規化（単一ドキュメント）
{
  _id: 1,
  name: "John",
  email: "john@example.com",
  posts: [
    { _id: 101, title: "Post 1", content: "..." },
    { _id: 102, title: "Post 2", content: "..." }
  ]
}
```

**注意点：** 非正規化はデータ重複が増え、更新時の一貫性維持が複雑になります。アクセスパターンを明確に定義してから設計します。

## 全文検索

**転置インデックス (Inverted Index)** は、全文検索エンジンの基盤です。単語→ドキュメントのマッピングを保持します。

```
単語「cat」→ [doc1, doc3, doc5]
単語「dog」→ [doc2, doc4, doc5]
```

**アナライザーとトークナイズ:**
- **トークナイズ：** テキストを単語に分割
- **正規化：** 大文字を小文字に、複数形を単数形に
- **ストップワード除去：** 「the」「a」など意味のない単語を削除
- **ステミング：** 語幹抽出（「running」→「run」）

**全文検索の実装:**
```javascript
// Elasticsearchの例
const searchResults = await client.search({
  index: 'articles',
  body: {
    query: {
      multi_match: {
        query: 'machine learning',
        fields: ['title', 'content'],
        fuzziness: 'AUTO'  // タイポ容認
      }
    }
  }
});
```

## 選定レポートの作成

データストア選定時は、以下を整理したレポートを作成します：

**セクション:**
1. **要件の整理：** アクセスパターン、スケール、一貫性要件
2. **候補データストア：** 各選択肢の特徴・メリット・デメリット
3. **比較表：** スケーラビリティ、遅延、運用複雑度の比較
4. **推奨選択：** 根拠を明記した推奨案
5. **リスク評価：** ベンダーロックイン、学習曲線

---

## ベストプラクティス

- **スキーマ設計の慎重性：** 変更が困難なため、要件整理を完全に実施
- **バックアップ戦略：** 各データストアのバックアップ・リカバリ方法を確認
- **監視・アラート：** ディスク使用量、接続数、クエリ性能の監視
- **マイグレーション計画：** 後付けでの変更が困難なため、初期設計が重要
