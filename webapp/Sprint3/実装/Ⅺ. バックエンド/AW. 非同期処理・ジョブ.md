# AW. 非同期処理・ジョブ

## 概要

バックエンドシステムでは、メール送信、画像処理、外部API呼び出しなど、時間のかかる処理をバックグラウンドで実行する必要があります。ジョブキューの管理、スケジューリング、イベント駆動アーキテクチャを理解することで、堅牢で拡張性の高いシステムを構築できます。

---

## 失敗と遅延の管理

非同期ジョブは、失敗（Failed）と遅延（Delayed）という2つの状態を管理する必要があります。

**Failed：** ジョブ実行中に予期しないエラーが発生した状態
- 再試行候補となるが、回数に上限を設ける
- エラーログとスタックトレースを保存
- アラート通知を送信

**Delayed：** ジョブが実行予定時刻に達していない、または一時的に遅延している状態
- スケジュール機能で実行時刻を指定
- キュー内で正しい順序で処理される必要がある

**管理のポイント:**
- 最大再試行回数の設定（例：3回まで）
- エクスポーネンシャルバックオフ（1秒 → 10秒 → 100秒）
- 遅延超過時の警告

---

## Dead Letter Queue (DLQ)

DLQは、複数回の再試行後も失敗し続けたジョブを格納するキューです。DLQに入ったジョブは自動処理から外され、手動介入が可能になります。

**DLQの仕組み:**
```
ジョブキュー → 失敗 → 再試行（指数バックオフ）
   ↓ （再試行回数超過）
Dead Letter Queue → 運用チームが手動確認 → 修正・再実行
```

**実装上の注意:**
- DLQに入ったジョブは詳細なメタデータを保持
- 一定期間後に自動削除するポリシー（例：30日後）
- DLQサイズの監視とアラート

## スケジューリング・定期実行

**Cron構文** は定期実行の仕様を表します。Unix/Linux標準の形式で、分・時・日・月・曜日の5フィールドで表現されます。

例：`0 2 * * *` は毎日2時00分実行

**node-cronによる実装:**
```javascript
import cron from 'node-cron';

// 毎日午前2時にデータベースクリーンアップ
cron.schedule('0 2 * * *', async () => {
  await cleanupExpiredSessions();
  console.log('Cleanup completed');
});

// 毎時00分にレポート生成
cron.schedule('0 * * * *', async () => {
  await generateHourlyReport();
});
```

**分散システムでのスケジューリング:**
複数サーバーで同じジョブが実行されないよう、分散ロック機構が必要です。データベースまたは専用キャッシュシステムを使用して、ジョブ実行権を制御します。

## イベント駆動アーキテクチャ

**密結合 vs 疎結合:**
密結合な実装では、ユーザー登録処理の中に「メール送信」と「データ分析」が直接記述されます。これはテストが困難で、機能追加時に既存コードを変更する必要があります。

疎結合なアーキテクチャでは、ユーザー登録時にイベント「UserCreated」を発行し、複数のリスナーがそのイベントに応答します。

**EventEmitterの実装:**
```javascript
import { EventEmitter } from 'events';

const userEvents = new EventEmitter();

// ユーザー登録処理
async function registerUser(email) {
  // ... 登録処理 ...
  userEvents.emit('userCreated', { email });
}

// リスナーの登録
userEvents.on('userCreated', async (user) => {
  await sendWelcomeEmail(user.email);
});

userEvents.on('userCreated', async (user) => {
  await recordUserAnalytics(user.email);
});
```

**メリット:**
- 機能追加が容易（新しいリスナーを追加するだけ）
- 単体テストが簡潔
- サービス間の依存性が低い

## バッチ処理

バッチ処理は、定期的に大量のデータを一括処理する手法です。チャンク分割して処理することで、メモリ効率を保ちます。
