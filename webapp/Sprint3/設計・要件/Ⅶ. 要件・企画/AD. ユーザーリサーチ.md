# AD. ユーザーリサーチ

## 概要

ユーザーリサーチは、ユーザーの潜在的ニーズを発掘し、プロダクト設計の基礎となるインサイトを獲得するプロセスです。ジョブ・ストーリーフレームワークを中心に、構造的なインタビューと分析を実施します。

---

## 1. ジョブ・ストーリー

ユーザーがシステムを使う本質的な「目的」「状況」「希望される結果」を捉えるフレームワークです。

**基本構造:**
```
「ユーザーが[状況]で[目的]を達成したい時、
 [希望される結果]が得られるソリューションが必要。」
```

**例：**
- 「営業担当者が営業訪問の移動中に、クライアント情報をすばやく確認したい時、モバイル検索が素早く動作することが必要。」

このフレームワークはペルソナより具体的で、ユースケースを正確に把握できます。

---

## 2. ユーザー調査の設計

**インタビューの準備:**
- **雇用と解雇の視点:** ユーザーが現在のソリューションを「雇用する」理由と「解雇する」理由を理解
- **4つの力（Forces）:**
  - Push: 現在のプロダクトの問題点がユーザーを新しいソリューションへ押す
  - Pull: 新しいソリューションの魅力がユーザーを引き寄せる
  - Habit: 既存習慣・移行コストの抵抗
  - Fear: 新しいソリューションへの不安
- **バイアスの回避:** 自社プロダクトに有利な質問は避け、ニュートラルな問いかけを心がける

---

## 3. インタビュー手法

**構造化と半構造化:**
- **構造化インタビュー:** 事前に決めた質問を同じ順序で実施。データ分析が容易だが、新たなインサイトが得られにくい
- **半構造化インタビュー:** ガイドを用意しつつ、流れに応じて質問を調整。柔軟性が高く、深いインサイトが期待できる

**インタビューガイド作成のポイント:**
- 背景質問（ユーザープロフィール、関連経験）
- ニーズ質問（現在の課題、既存ソリューション）
- シナリオ質問（具体的な利用場面での行動）
- フォローアップ質問（「なぜ？」を繰り返す）

---

## 4. 競合分析と共有化

**競合の見直し:**
- 直接競合（同じカテゴリの製品）
- 間接競合（代替手段や代替プロダクト）
- ユーザーが採用している非公式な解決策も調査

**情報の共有と構造化:**
- **親和図法:** インタビュー内容をカード化して分類し、共通パターンを抽出
- **KA法（要素列挙法）:** ユーザーの行動や思考を細かく列挙して、見落としを防ぐ

```python
# インタビュー分析の例
interview_insights = {
    "ペイン": ["情報検索に時間がかかる", "複数ツール間の切り替えが面倒"],
    "ニーズ": ["統合検索", "リアルタイム更新"],
    "既存解決策": ["Googleドライブ", "Slack"],
    "競合": ["Notion", "Confluence"]
}
```

---

## 5. インサイトの活用

インタビュー結果から得られたインサイトを、プロダクト設計に直結させます。

- 最頻出の課題から優先度を決定
- ユースケース（ジョブ・ストーリー）として文書化
- UI設計やプロトタイピングの指針に反映

複数回の調査サイクルを実施し、仮説の検証と新たなインサイト発掘を繰り返すことが重要です。
