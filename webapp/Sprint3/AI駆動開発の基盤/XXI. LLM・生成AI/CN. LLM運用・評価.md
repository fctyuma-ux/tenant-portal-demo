# CN. LLM運用・評価

## 概要

LLMの本番運用では、ガードレール、継続的な評価、フィードバックループ、バージョニングが必須です。これらにより、安全性を確保しながら品質を継続的に改善します。

---

## 1. ガードレール実装

入出力の内容をフィルタリングして、有害な内容や機密情報の露出を防ぎます。

**入力ガードレール:**
- プロンプトインジェクション攻撃の検出
- 有害なコンテンツ（暴力、不正行為など）の検出
- 機密情報（APIキー、パスワードなど）の検出
- 不適切な言語・表現の検出

**出力ガードレール:**
- LLMの出力に含まれた有害コンテンツの検出
- 生成テキストに含まれた機密情報のマスキング
- 回答の完全性・正確性の事前チェック

```python
# ガードレール実装例
def process_user_input(user_input):
    if detect_injection_attack(user_input):
        return "不正なリクエストです"

    masked_input = mask_sensitive_info(user_input)
    response = llm.generate(masked_input)

    if contains_harmful_content(response):
        return "申し訳ございません、お答えできません"

    return response
```

---

## 2. LLM評価フレームワーク

LLMの出力品質を多角的に測定・改善する仕組みです。

**評価次元:**
- **正確性（Accuracy）:** 事実に基づいた回答であるか
- **関連性（Relevance）:** ユーザーのクエリに適切に応答しているか
- **一貫性（Consistency）:** 複数回の実行で同様の品質を保つか
- **完全性（Completeness）:** 必要な情報を十分に提供しているか

**LLM-as-a-Judge:** LLMを評価者として活用し、大規模なデータセットを自動評価。人間の評価結果との相関が高く、実用性が高いアプローチです。

---

## 3. 継続的改善サイクル

フィードバックを収集し、プロンプトやモデル選択を反復的に改善します。

**サイクルの構成:**
1. ベースラインの設定（初期プロンプトでの性能測定）
2. 改善仮説の立案（プロンプト最適化、モデル変更など）
3. 評価データセットでの検証
4. 改善前後の性能比較
5. 有効な改善の本番反映

継続的にユーザーフィードバックを収集し、低品質な応答を分析して改善につなげます。

---

## 4. バージョニングと変更管理

プロンプト、モデル、ルール設定のバージョンを管理し、ロールバック可能にします。

**管理項目:**
- **プロンプトのGit管理:** テンプレート、パラメータを厳密に版管理
- **モデルバージョンの記録:** 使用モデルとそのアップデート日時を追跡
- **セマンティックバージョニング:** Major.Minor.Patch形式で変更内容を表現
- **変更ログ（Changelog）:** 各バージョンの変更内容と理由を記載
- **並行運用（Canary Deployment）:** 新バージョンを一部ユーザーで試験

```python
# バージョニング管理例
prompt_version = "1.2.3"  # Major.Minor.Patch
deployment_config = {
    "prompt": load_prompt(version="1.2.3"),
    "model": "gpt-4-turbo",
    "model_version": "2024-01",
    "canary_percentage": 10  # 10%ユーザーで試験
}
```

---

## 5. 運用ダッシュボード

LLMの品質状況をリアルタイムで可視化し、問題を早期発見します。

**追跡指標:**
- ユーザー満足度（NPS、明示的フィードバック）
- 応答品質スコア（自動評価結果）
- エラー率・ガードレール適用率
- レイテンシ・トークン使用量
- コスト（API呼び出しベース）

回帰テストを自動化し、新バージョン導入時に過去の品質が維持されていることを確認します。
