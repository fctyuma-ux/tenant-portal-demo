# CL. RAG（検索拡張生成）

## 概要

RAG（検索拡張生成）は、LLMの知識ベースをリアルタイムで外部データから検索・参照することで、より正確で最新の回答を生成するアプローチです。チャンキング、検索、フィルタリングという3つの主要なステップで構成されます。

---

## 1. チャンキング戦略

大規模なテキストをLLMの処理可能な単位に分割する工程です。固定サイズ、セマンティック、階層的チャンキングなど複数の手法があります。

**主要な手法:**
- **固定サイズチャンキング:** 一定の単語数や文字数で機械的に分割。実装が簡単だが、文境界を無視する
- **セマンティックチャンキング:** 文の意味を考慮して分割。情報の一貫性が高いが計算コストが増加
- **階層的チャンキング:** 複数の粒度でチャンクを作成。多様な検索要求に対応可能
- **オーバーラップ（重複）:** チャンク間に重複を設け、境界での情報欠落を防止

---

## 2. 検索精度の向上

検索結果の質がRAGの出力品質に直結します。キーワード検索、ハイブリッド検索、Rerankingなどの技術で精度を高めます。

**検索手法:**
- **キーワード検索（BM25）:** 統計的な関連性スコアリング。高速で解釈性が高い
- **ハイブリッド検索:** キーワード検索とベクトル検索を組み合わせ。単一の手法より優れた精度
- **クエリ拡張:** 元のクエリを拡張・言い換えて検索ヒット率を向上
- **Reranking（再ランキング）:** 初期検索結果を専門の再評価モデルで再順序付け

---

## 3. メタデータと権限管理

検索結果に対して権限ベースのフィルタリングやカテゴリ別の制限を適用する戦略です。

**実装例:**
- メタデータの定義（作成者、日付、重要度、アクセス権など）
- カテゴリフィルタリング、日付範囲フィルタリング
- マルチテナント環境での権限ベースフィルタリング
- 複合条件フィルタリング（複数フィルタの組み合わせ）

```python
# ハイブリッド検索 + メタデータフィルタリング例
search_results = hybrid_search(
    query="API設計のベストプラクティス",
    keyword_weight=0.4,
    vector_weight=0.6,
    filters={"category": "API", "date_from": "2024-01-01"}
)

reranked = rerank(search_results, top_k=5)
```

## 4. パラメータチューニング

チャンクサイズ、検索パラメータ、フィルタ条件の最適化により、検索精度と検索速度のバランスを取ります。

**調整ポイント:**
- チャンクサイズ（500-1000トークン推奨）
- オーバーラップ率（10-20%推奨）
- 返却チャンク数（3-5個が一般的）
- キーワード/ベクトル検索の重み配分

```python
# パラメータチューニング実施例
```

---

## 5. 評価と改善

検索精度の評価指標を定義し、継続的に改善を実行します。

**評価指標:**
- **Precision@k:** 上位k件中の関連性のある割合
- **Recall:** 全関連文書に対する検索ヒット率
- **MRR（Mean Reciprocal Rank）:** 最初に関連文書が出現する順位の平均逆数
- **NDCG（正規化割引累積利得）:** ランキングの質を総合的に評価

継続的に検索パラメータをチューニングし、低品質な回答を分析して改善サイクルを実施します。
