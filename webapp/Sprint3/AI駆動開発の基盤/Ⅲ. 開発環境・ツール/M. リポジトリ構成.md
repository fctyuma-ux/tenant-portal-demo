# M. リポジトリ構成

## 概要

リポジトリ構成は複数パッケージ・モジュールの依存関係、共有方法、ビルドパイプラインを決めます。モノレポ採用、ワークスペース設定、タスク並列化により、スケーラブルで保守性の高い開発環境を実現します。

---

## 1. モノレポ vs ポリレポ

| 項目 | モノレポ | ポリレポ |
|---|---|---|
| 構成 | 単一リポ複数パッケージ | 独立リポ |
| 依存管理 | 統一版 | 各自管理 |
| コード共有 | 容易 | npmパッケージ化必要 |
| CI/CD | 統一 | 独立 |
| 影響範囲 | 算出可能 | 手動判断 |

---

## 2. Workspaces

複数パッケージを効率管理

```json
{
  "workspaces": ["packages/*"]
}
```

パッケージ間参照：
```json
{
  "dependencies": {
    "@myapp/shared": "workspace:*"
  }
}
```

**利点：** 統一版管理、ローカル即座反映、一括テスト

---

## 3. hoist と依存解決

| ツール | 方式 | 特徴 |
|---|---|---|
| **npm** | hoisting | node_modules フラット |
| **yarn** | hoisting | ディレクトリ浅い |
| **pnpm** | non-hoisting | 幽霊依存排除 |

---

## 4. ロックファイルと CI 再現性

```
package.json     → 許容範囲（^1.2.3）
package-lock.json → 正確版（1.2.5）
```

CI推奨：`npm ci`, `yarn install --frozen-lockfile`

---

## 5. 共有パッケージ設計

**共有対象：** ユーティリティ、型定義、UIコンポーネント

**内部 vs 公開：**
```
shared/
├── internal/   ← パッケージ内のみ
├── public/     ← 他パッケージ利用
└── index.ts    ← エントリーポイント
```

---

## 6. 依存ルール（循環依存回避）

```
frontend → shared ← backend
```

循環依存（frontend ↔ backend）は禁止

---

## 7. バージョニング戦略

**同一バージョン:** すべてパッケージ同じ版

**独立バージョン:** パッケージごと独立

---

## 8. タスク実行とキャッシュ

**タスクランナー:** 複数パッケージのtest/build調整

```bash
pnpm -r test              # 全テスト
pnpm nx test --affected   # 影響範囲のみ
```

**キャッシュ：** ローカル（前回output再利用）、リモート（CI共有）

**並列実行:** 依存関係に基づき順序制御

---

## 9. ツール比較

| ツール | 特徴 | 用途 |
|---|---|---|
| **Turborepo** | 高速、キャッシュ豊富 | 大規模monorepo |
| **Nx** | affected自動検出 | フレームワーク統合 |
| **Lerna** | npm publish管理 | npm公開 |
| **pnpm** | シンプル内蔵 | 小～中規模 |

---

## 10. 実践スキル

- monorepo構築とworkspaces設定
- 依存ルール導入と違反検出
- タスクパイプライン構築
- キャッシュ効果測定
