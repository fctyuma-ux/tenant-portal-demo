# G. 言語共通の応用概念

## 概要

並行・並列処理は現代システムの核です。複数の処理を安全に実行し、データ競合やデッドロックを避けることは全言語共通の課題です。概念を理解し、各言語での実装パターンを習得します。

---

## 1. 並行 vs 並列

**並行（Concurrency）:** 複数タスクが同時間枠で「進む」（時間軸で重なる）
- 1コアで複数タスクを切り替え
- I/O待機中に別タスク実行

**並列（Parallelism）:** 複数タスクが物理的に「同時に」実行
- 複数コアで同時実行
- 真の並行実行

```
並行：[Task A]--[Task B]--[Task A]（1コア、交互）
並列：[Task A] [Task B]（複数コア同時）
```

---

## 2. 実行単位の比較

| 単位 | メモリ分離 | コスト | 用途 |
|---|---|---|---|
| **プロセス** | あり | 大 | 独立プログラム |
| **スレッド** | なし | 中 | 並行処理 |
| **コルーチン** | なし | 小 | async/await |

---

## 3. データ競合と可視性問題

**データ競合:** 複数スレッドが共有データに同時アクセス

```javascript
counter = 0;
thread1: counter++;  // 期待: 2
thread2: counter++;  // 実際: 1（競合！）
```

**可視性問題:** スレッドAの変更がスレッドBに見えない
- CPUキャッシュに留まり、メモリに書き込まれない

---

## 4. 同期制御メカニズム

| 機構 | 説明 | 利点 |
|---|---|---|
| **Mutex** | 一度に1スレッド | シンプル |
| **Semaphore** | 複数スレッド許可 | 制御柔軟 |
| **Channel** | メッセージ送受信 | 安全性高 |

---

## 5. デッドロック

複数スレッドが互いを待機し永遠に進まない状態

```
Thread A: Lock(X) → Lock(Y) 待機
Thread B: Lock(Y) → Lock(X) 待機
```

**回避策：** ロック順序統一、タイムアウト、チャネル使用

---

## 6. ワーカープール

```
[Task Queue] → [Worker1, Worker2, Worker3]
タスク効率管理、スレッド数制限
```

---

## 7. 実践スキル要件

- データ競合再現とロック追加で修正
- ワーカープール実装（キュー→処理）
- デッドロック検出と回避策
- 並列化の効果計測（時間比較）
