# プロジェクト管理

## 概要

プロジェクト管理は技術スキルと同等かそれ以上に重要です。本セクションでは見積もり、スケジュール管理、リスク管理、チーム内コミュニケーション、課題発生時の対応をカバーします。

各フェーズで体系的に計画・実行・監視することで、デリバリーの予測可能性と品質を高めます。

---

## 1. 見積もりと計画

**相対見積もりの実践**
- 絶対的な時間ではなく、タスク相互の相対的な大きさを比較
- ポイント制：1 point = 簡単、3 = 中程度、5 = 複雑、8 = 非常に複雑
- メリット：チーム経験に基づいた現実的な見積もり

**見積もりプロセス**
```
1. タスク説明を読む（全員が理解）
2. 各人が独立して見積もり（他人の影響を受けない）
3. 見積もり値を開示
4. 意見が異なる場合は質問（「なぜ 5？」「なぜ 8？」）
5. 納得したら確定
```

**バッファの計算**
```
プロジェクト総時間 = Σ(タスク時間) × 1.3 ～ 1.5

例：
- 確実なタスク：30 時間
- バッファ（30％）：9 時間
- 計画時間：39 時間
```

バッファは予期しない問題や学習コストをカバーします。

## 2. スケジュール管理

**スケジュールの作成**
```
Phase 1: 要件定義・設計（2週間）
  ├─ ユーザーストーリー作成：4日
  ├─ 技術調査：3日
  └─ 設計レビュー：3日

Phase 2: 実装（4週間）
  ├─ バックエンド実装：2週間
  ├─ フロントエンド実装：1.5週間
  └─ 統合テスト：3.5日

Phase 3: テスト・リリース（1.5週間）
  ├─ バグ修正：1週間
  ├─ 本番環境テスト：3日
  └─ リリース・モニタリング：2日
```

**クリティカルパスの認識**
- 遅延するとプロジェクト全体が遅延するタスクを優先化
- 依存関係を明確化し、並行実行できるタスクを検出

---

## 3. 遅延対応シミュレーション

**問題発生時の対応フロー**
```
1. 問題を早期に検知
   → 日次スタンドアップで「進捗が予定より遅い」を報告

2. 原因を分析
   → 想定外の技術的障害？ 要件の不明確さ？

3. 対応案を複数検討
   → スコープ削減（MVP化）
   → 人員追加
   → 納期延期

4. ステークホルダーへ報告
   → 影響範囲と代替案を説明
```

**遅延の予防策**
- 技術的リスクは早期に検証
- 新しい技術スタックは事前に PoC（概念実証）
- チーム内の知識共有で依存性を減らす

## 4. リスク管理

**リスク洗い出し会**
- 参加者：PO、エンジニア、デザイナー、QA、管理職
- 手法：ブレインストーミング「何が起こったら困るか」
- 記録：リスク ID、説明、影響度、確度（発生可能性）

**リスク管理表の運用**
```
| ID | リスク内容 | 影響 | 確度 | 対応策 | 担当 | 進捗 |
|----|----------|------|------|--------|------|------|
| R1 | 外部API が遅い | 高 | 中 | 事前にキャパテスト | 太郎 | 実施済 |
| R2 | エンジニア離職 | 高 | 低 | ドキュメント作成 | 花子 | 進行中 |
| R3 | セキュリティ脆弱性 | 高 | 中 | セキュリティ監査 | 次郎 | 検討中 |
```

**優先化基準**
- **対応優先順**：影響度 × 確度 の高い順
- **定期レビュー**：週 1 回、新しいリスクを追加・クローズ

## 5. チーム内コミュニケーション

**コミュニケーション計画**
```
毎日：スタンドアップ（15分）
  - 昨日の成果、今日のゴール、ブロッカー

週1回：進捗レビュー（1時間）
  - 各タスクの進捗率、リスク状況、決定事項

月1回：レトロスペクティブ（1時間）
  - 良かった点、改善点、次月への提案

随時：1on1（週1回、30分）
  - 個別の課題・成長支援
```

**悪い知らせの伝達**
```
1. タイミングを優先（遅延は避ける）
   → 「実は計画より 2 週間遅延しそうです」（早期報告）

2. 原因と影響を明確に
   → 「なぜ遅延？」「プロジェクト全体はどうなる？」

3. 代替案を用意
   → スコープ削減、納期延期、人員追加のオプション

4. 信頼を失わない
   → 「責任を取ります」「以後このミスは防ぎます」
```

## 6. ステータス報告と可視化

**ステータスダッシュボード**
```
プロジェクト進捗：65% 完了（計画 60%、予定より進んでいる）

タスク状況：
  完了（Green）：15タスク
  進行中（Yellow）：8タスク（予定通り）
  遅延（Red）：2タスク（要注視）

リスク：3件（High:1, Medium:2）

今週のアクション：
  - データベース設計完了
  - API テスト開始
  - セキュリティ監査実施
```

適切な可視化でステークホルダーの信頼を獲得します。
