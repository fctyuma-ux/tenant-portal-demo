# X. その他の開発手法

## 概要

**フィーチャー駆動開発（Feature-Driven Development）** は、小さく具体的な単位「フィーチャー」を中心に進捗を管理するアジャイル手法です。見積りと完了判定が明確になり、チーム全体で進捗を可視化しやすくなります。

---

## フィーチャーリスト（Feature List）の作り方

**フィーチャーの定義:**

フィーチャーは「ユーザーに価値をもたらす、完成可能な最小単位」です。

**特徴:**
- ユーザーストーリーより具体的（技術的にも詳細）
- 見積り可能な粒度（1～5日を目安）
- 完了判定基準が明確

**作成フロー:**

1. プロダクトバックログから要件を選別
2. 各要件を複数の小さなフィーチャーに分割
3. 優先度とビジネス価値を付与
4. 実装順序（依存関係）を決定

**フィーチャーリスト例:**

```
Feature List: ユーザー認証
├─ F1: メールアドレス登録フォームの実装（2日）
├─ F2: メール検証プロセス（1日）
├─ F3: パスワード設定画面（1日）
└─ F4: ログイン機能とセッション管理（3日）
```

---

## モデル/設計の位置づけ

全体モデル（ドメインモデル）→ フィーチャーモデル → 実装 の階層構造。チーム全体が共通の設計イメージを持ち、並列開発が容易になります。

---

## フィーチャー駆動の見積りと進捗

見積り：1/5/10ポイント（相対値）または1～5日。フィーチャー単位で状態管理（設計中 → 実装中 → テスト中 → 完成）。

---

## フィーチャーリストを作って優先順位付けできる

ビジネス価値スコア、技術リスク、依存関係、実現可能性で優先度決定。高価値・低リスク から実装開始。

---

## フィーチャー単位で「完了」の定義を置ける

完了基準：実装 → ユニットテスト → 統合テスト → ドキュメント更新 → Code Review → パフォーマンス確認。
