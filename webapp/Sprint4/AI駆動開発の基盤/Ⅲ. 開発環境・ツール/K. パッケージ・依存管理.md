# K. パッケージ・依存管理

## 概要

SBOMは、ソフトウェアに含まれるすべてのコンポーネント・ライブラリ・依存関係を記録したドキュメントです。セキュリティ脆弱性の追跡、ライセンス管理、サプライチェーン攻撃への対策に不可欠な存在となっています。

---

## SBOMとは

**SBOM（Software Bill of Materials）** は、建築物の部品表に相当するソフトウェア版です。プロダクトに組み込まれたすべてのライブラリ、フレームワーク、その他のコンポーネントをリストアップしています。

**包含される情報:**
- コンポーネント名とバージョン
- ライセンス情報
- 脆弱性ID（CVE）への関連付け
- 出所（オープンソース / 商用）

---

## SBOMが必要になる状況

SBOMが重要になるケースは以下の通りです：

1. **サイバーセキュリティ対応**：新しい脆弱性が公開された時、自社製品が影響を受けるかを素早く判定
2. **ライセンスコンプライアンス**：GPL等の制限的ライセンスが混在していないかの確認
3. **サプライチェーン攻撃対策**：依存パッケージへのマルウェア混入を検出
4. **監査・報告**：顧客やセキュリティ認証機関への報告書として

---

## フォーマット（SPDX/CycloneDX）と生成ツールの概念

SBOMを記述するための標準フォーマットが2つあります：

**SPDX（Software Package Data Exchange）**
- より詳細でフォーマルな記述
- 複雑なプロジェクト向け

**CycloneDX**
- よりシンプルでコンパクト
- JSON/XML形式でツール連携が容易

**生成ツール:**
- npm: `npm-audit` / `syft` による自動生成
- Java: `CycloneDX Maven Plugin`
- Python: `cyclonedx-bom`

```json
{
  "bomFormat": "CycloneDX",
  "version": 1,
  "components": [
    {
      "type": "library",
      "name": "lodash",
      "version": "4.17.21",
      "licenses": [{"license": {"name": "MIT"}}]
    }
  ]
}
```

---

## SBOMを生成し、内容を説明できる

実装の流れ：

1. プロジェクトディレクトリで生成ツールを実行
2. JSON または XML 形式のBOMファイルを出力
3. 出力されたファイルからコンポーネント数、ライセンス分布、既知脆弱性を読み取る

```bash
# npm プロジェクトの場合
npx syft . -o cyclonedx-json > sbom.json
```

## CIに組み込み、保管/配布方針を決められる

**CI統合:**
- ビルドパイプラインでSBOM生成を自動化
- 脆弱性スキャン結果を記録
- 失敗時はアラートまたはログ記録

**保管方針:**
- アーティファクトリポジトリに SBOM を格納
- 本体コード同様、バージョン管理
- 監査用に過去3年分保持

**配布方針:**
- 外部セキュリティ監査が必要な場合は配布
- 内部メンバーのみアクセス可能な環境で共有
- GDPR等で機密部分をマスク
