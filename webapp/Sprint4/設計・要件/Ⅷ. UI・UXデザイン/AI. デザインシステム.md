# AI. デザインシステム

## 概要

**デザインシステム** は、UIコンポーネント、配色、タイポグラフィなどの設計ルールを一元管理し、プロダクト全体の一貫性を保つための仕組みです。チーム規模が大きいほど、デザイン負債を避けるため、システム化が重要になります。

---

## 一貫性のレベル

デザイン一貫性の度合いは、プロダクトの段階によって段階的に高まります。

**レベル1: 基本的一貫性**
- 色パレットが統一されている
- フォント は2-3種類に限定
- 例）プロトタイプ段階

**レベル2: コンポーネント一貫性**
- 頻出UI（ボタン、フォーム等）が統一デザイン
- 異なるページでも同じコンポーネントを再利用
- 例）Alpha 版、ベータ版

**レベル3: システム一貫性**
- 全コンポーネントが管理されている
- 設計トークン（色値、フォントサイズ）が一元化
- 変更は1箇所で全体に反映
- 例）本番環境、フル運用

---

## デザイン負債

デザイン負債とは、場当たり的な設計の積み重ねです。

**例:**

- ボタンの色が10パターン混在している
- フォントサイズが統一されていない
- クリックエリアの大きさが異なる
- ホバー状態が定義されていない

**負債が生じる原因:**
- チーム拡大時に設計ルール未整備
- 急速な機能追加で、デザインを後付けした
- 複数デザイナーが別々のツールで作業

**デザイン負債の削減方法:**

1. 現状を把握（全ページ / コンポーネント調査）
2. 統一ルール定義
3. 既存UI を段階的に修正
4. 新規機能は必ずシステムに従う

## Design Lintの活用

デザインの品質をチェックするツール。コード書き込み前に設計を検証します。

**Design Lint チェック内容:**

- テキスト色とBackground のコントラスト比（WCAG基準：4.5:1以上）
- 使用フォントが定義セット内か
- 余白（マージン/パディング）が設計トークンに従っているか
- コンポーネント名が命名規則に従っているか

**ツール例:** Figma Plugins（Color Contrast Checker等）

---

## コンポーネント更新フロー

Figma 更新 → Code Review → Component Library へ merge → 全ページに自動反映 → QA 検証。バージョン管理でロールバック対応。

---

## カラーパレット管理

Primary、Secondary、Neutral、Semantic 色を定義。Primary は濃淡（Dark/Light）で バリエーション提供。

---

## Storybook などの設計カタログ

コンポーネントをビジュアルで示すカタログ。ビジュアル、Props、使用例、アクセシビリティ情報を記載。

---

## デザイン監査

定期的にデザイン一貫性をチェック。色使い、タイポグラフィ、アイコン、ボタンサイズ、レスポンシブ対応を確認。
