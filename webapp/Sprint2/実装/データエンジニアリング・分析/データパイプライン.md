# データパイプライン

## 概要

データパイプラインは、データの抽出・変換・ロードの一連のプロセスを自動化・オーケストレーションするシステムです。ETL と ELT の使い分け、冪等性の確保、DAG（有向非巡回グラフ）による依存管理が堅牢なパイプライン構築の要です。バリデーションとエラーハンドリングにより、データ品質を維持します。

---

## 1. ETL vs ELT

**役割:** データ統合の方式を選択

### ETL（Extract → Transform → Load）

**流れ:** ソース → 中間層（変換） → データウェアハウス

```
Raw Data → Staging Server → Processed Data → DW
              (Transform)
```

**特徴:**
- 変換を別プロセスで実施
- DW に入る前に品質確保
- ストレージ効率が良い

**Python での実装例:**
```python
import pandas as pd
from sqlalchemy import create_engine

# Extract
source_data = pd.read_csv('raw_data.csv')

# Transform
processed_data = source_data.copy()
processed_data['revenue'] = processed_data['price'] * processed_data['quantity']
processed_data = processed_data[processed_data['revenue'] > 0]  # 無効データ削除
processed_data['date'] = pd.to_datetime(processed_data['date'])

# Load
engine = create_engine('postgresql://user:pass@localhost/dw')
processed_data.to_sql('orders', engine, if_exists='append', index=False)
```

### ELT（Extract → Load → Transform）

**流れ:** ソース → DW（そのままロード） → DW内で変換

```
Raw Data → DW (as-is) → Transformed Data
           (Transform in SQL)
```

**特徴:**
- スケーラブル（DW の計算力を活用）
- スキーマ変更に強い（変換はあとから）
- DW にraw データを蓄積

**SQL での実装例:**
```sql
-- 1. Raw テーブルに全データをロード
CREATE TABLE staging_orders AS
SELECT * FROM source_system;

-- 2. DW で変換
CREATE TABLE dw_orders AS
SELECT
  order_id,
  customer_id,
  price * quantity AS revenue,
  DATE(order_date) AS date
FROM staging_orders
WHERE price * quantity > 0;
```

**選択基準:**
| 条件 | ETL | ELT |
|------|-----|-----|
| DW の計算力 | 弱い | 強い（Snowflake等） |
| スキーマ変更頻度 | 低い | 高い |
| レイテンシ | 許容 | 低い |

## 2. 冪等性（Idempotency）

**役割:** パイプライン再実行時に同じ結果を保証

冪等性なしでは、再実行時にデータが重複・矛盾する。

**非冪等な例（危険）:**
```python
# 危険: 再実行時に重複が発生
def load_data():
    df = pd.read_csv('data.csv')
    # INSERT INTO ... (重複キーがあると失敗)
    df.to_sql('users', engine, if_exists='append')
```

**冪等な実装:**
```python
def load_data():
    df = pd.read_csv('data.csv')

    # 1. UPSERT（Merge）パターン
    # DELETE → INSERT（既存データを消してから再作成）
    engine.execute("DELETE FROM users WHERE date = DATE(%s)", date.today())
    df.to_sql('users', engine, if_exists='append', index=False)

    # 2. SELECT → INSERT パターン
    existing = pd.read_sql("SELECT id FROM users", engine)
    new_users = df[~df['id'].isin(existing['id'])]
    new_users.to_sql('users', engine, if_exists='append', index=False)
```

**SQL での冪等性:**
```sql
-- 再実行可能なパイプライン
DELETE FROM daily_summary WHERE date = '2024-01-01';

INSERT INTO daily_summary (date, total_revenue)
SELECT
  DATE(order_date),
  SUM(amount)
FROM orders
WHERE DATE(order_date) = '2024-01-01'
GROUP BY DATE(order_date);
```

## 3. DAG（Directed Acyclic Graph）による依存管理

**役割:** タスク間の依存関係を定義し、効率的に実行

### 簡易DAGの作成

```python
from collections import defaultdict, deque

class DAG:
    def __init__(self):
        self.graph = defaultdict(list)
        self.in_degree = defaultdict(int)

    def add_task(self, task, depends_on=None):
        """タスクを追加"""
        if depends_on is None:
            depends_on = []

        for dep in depends_on:
            self.graph[dep].append(task)
            self.in_degree[task] += 1

    def topological_sort(self):
        """実行順序を決定"""
        queue = deque([t for t in self.in_degree if self.in_degree[t] == 0])
        result = []

        while queue:
            task = queue.popleft()
            result.append(task)

            for neighbor in self.graph[task]:
                self.in_degree[neighbor] -= 1
                if self.in_degree[neighbor] == 0:
                    queue.append(neighbor)

        return result if len(result) == len(self.in_degree) else None

# 使用例
pipeline = DAG()
pipeline.add_task('fetch_raw_data')
pipeline.add_task('clean_data', ['fetch_raw_data'])
pipeline.add_task('transform_data', ['clean_data'])
pipeline.add_task('load_to_dw', ['transform_data'])
pipeline.add_task('notify', ['load_to_dw'])

order = pipeline.topological_sort()
print(order)  # ['fetch_raw_data', 'clean_data', 'transform_data', 'load_to_dw', 'notify']
```

## 4. バリデーションとインプット検証

**役割:** データ品質を確保し、下流へのトラブル伝播を防ぐ

```python
def validate_data(df):
    """複数のバリデーションを実行"""
    errors = []

    # 1. 必須カラムチェック
    required_columns = ['id', 'email', 'created_at']
    missing = set(required_columns) - set(df.columns)
    if missing:
        errors.append(f'Missing columns: {missing}')

    # 2. 重複チェック
    if df['id'].duplicated().any():
        errors.append('Duplicate IDs found')

    # 3. データ型チェック
    try:
        df['created_at'] = pd.to_datetime(df['created_at'])
    except:
        errors.append('Invalid date format in created_at')

    # 4. 値の範囲チェック
    if (df['age'] < 0).any() or (df['age'] > 150).any():
        errors.append('Age out of valid range')

    # 5. スキーマ変更の検知
    schema_version = df.attrs.get('schema_version', 1)
    if schema_version != CURRENT_SCHEMA:
        errors.append(f'Unexpected schema version: {schema_version}')

    if errors:
        raise ValueError('\n'.join(errors))

    return df

# バリデーション実施
try:
    df = pd.read_csv('input.csv')
    validate_data(df)
except ValueError as e:
    # Dead Letter Queue に送信
    send_to_dlq('validate_failure', str(e), df)
    raise
```

## 5. Dead Letter Queue（DLQ）

**役割:** 失敗したデータを別の場所に隔離し、後で調査・修復

```python
import json
from datetime import datetime

def send_to_dlq(reason, error_msg, data):
    """失敗データを DLQ に記録"""
    dlq_record = {
        'timestamp': datetime.utcnow().isoformat(),
        'reason': reason,
        'error': error_msg,
        'data': data.to_dict() if hasattr(data, 'to_dict') else data,
        'retry_count': 0,
        'next_retry': None
    }

    # ファイルまたは専用テーブルに記録
    with open('dlq.jsonl', 'a') as f:
        f.write(json.dumps(dlq_record) + '\n')

    print(f'[DLQ] {reason}: {error_msg}')

# パイプラインでの使用
def process_pipeline(data):
    try:
        validate_data(data)
        transform_data(data)
        load_data(data)
    except Exception as e:
        send_to_dlq('processing_failure', str(e), data)
```

## 6. バックフィル（Backfill）

**役割:** パイプライン変更後に過去データを再処理

```python
from datetime import datetime, timedelta

def backfill(start_date, end_date):
    """過去データを再処理"""
    current_date = start_date

    while current_date <= end_date:
        print(f'Processing {current_date}...')

        try:
            data = fetch_data(current_date)
            validate_data(data)
            transform_data(data)
            load_data(data)
            print(f'✓ {current_date} completed')

        except Exception as e:
            print(f'✗ {current_date} failed: {e}')
            send_to_dlq('backfill_failure', str(e), data)

        current_date += timedelta(days=1)

# 使用例
backfill(
    start_date=datetime(2024, 1, 1),
    end_date=datetime(2024, 1, 31)
)
```

## 7. バッチウィンドウとマイクロバッチ

**バッチウィンドウ:** 1日1回など、定期的に実行
```python
# 毎日午前3時に実行
0 3 * * * python /path/to/daily_pipeline.py
```

**マイクロバッチ:** 1時間ごと、30分ごとなど、頻繁に実行
```python
# 1時間ごとに実行
0 * * * * python /path/to/hourly_pipeline.py
```

**選択基準:**
| 要件 | 方式 |
|------|------|
| リアルタイム性が低い | バッチウィンドウ |
| 数時間の遅延許容 | マイクロバッチ |
| リアルタイム性が高い | ストリーム処理 |
