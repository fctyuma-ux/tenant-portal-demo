# データ分析・可視化

## 概要

データ分析は、集計・統計・ウィンドウ関数を用いてビジネスインサイトを抽出するプロセスです。可視化により複雑なデータを視覚的に伝え、ダッシュボードでストーリーテリングを実現します。BIツールの選択、ディメンション・メジャーの設計、統計的基礎が分析の質を左右します。

---

## 1. SQL による集計と分析

**役割:** データベースで効率的に集計を実施

### 集計関数と GROUP BY

```sql
-- 基本的な集計
SELECT
  category,
  COUNT(*) AS product_count,
  AVG(price) AS avg_price,
  MAX(price) AS max_price,
  SUM(quantity) AS total_quantity
FROM products
GROUP BY category;

-- HAVING で集計結果をフィルタ
SELECT
  category,
  COUNT(*) AS product_count
FROM products
GROUP BY category
HAVING COUNT(*) > 10;  -- 商品数が10個以上のカテゴリ
```

### ウィンドウ関数（Window Functions）

各行に対して、グループ内の集計結果を付与。

```sql
-- 月ごとの売上と累積売上
SELECT
  DATE_TRUNC('month', order_date) AS month,
  SUM(amount) AS monthly_revenue,
  SUM(SUM(amount)) OVER (ORDER BY DATE_TRUNC('month', order_date))
    AS cumulative_revenue
FROM orders
GROUP BY DATE_TRUNC('month', order_date);

-- ランキング（ROW_NUMBER, RANK, DENSE_RANK）
SELECT
  customer_id,
  order_date,
  amount,
  ROW_NUMBER() OVER (ORDER BY amount DESC) AS rn,
  RANK() OVER (ORDER BY amount DESC) AS rank,  -- 同点の場合スキップ
  DENSE_RANK() OVER (ORDER BY amount DESC) AS dense_rank  -- スキップなし
FROM orders
LIMIT 10;

-- 前月比
SELECT
  month,
  revenue,
  LAG(revenue) OVER (ORDER BY month) AS prev_month_revenue,
  ROUND(
    (revenue - LAG(revenue) OVER (ORDER BY month))
    / LAG(revenue) OVER (ORDER BY month) * 100, 2
  ) AS pct_change
FROM monthly_sales;
```

## 2. CTE（Common Table Expressions）

**役割:** 複雑なクエリを段階的に構築

```sql
-- RFM 分析（Recency, Frequency, Monetary）
WITH customer_stats AS (
  SELECT
    customer_id,
    MAX(order_date) AS last_purchase,
    COUNT(*) AS purchase_frequency,
    SUM(amount) AS total_spent,
    CURRENT_DATE - MAX(order_date) AS days_since_last
  FROM orders
  GROUP BY customer_id
),
rfm_scores AS (
  SELECT
    customer_id,
    NTILE(5) OVER (ORDER BY days_since_last DESC) AS r_score,
    NTILE(5) OVER (ORDER BY purchase_frequency DESC) AS f_score,
    NTILE(5) OVER (ORDER BY total_spent DESC) AS m_score
  FROM customer_stats
)
SELECT
  customer_id,
  r_score,
  f_score,
  m_score,
  CONCAT(r_score, f_score, m_score) AS rfm_segment
FROM rfm_scores
WHERE r_score >= 4 AND f_score >= 4 AND m_score >= 4;  -- 優良顧客
```

## 3. 統計分析

**役割:** データの分布・相関・外れ値を把握

### 基本統計量

```sql
SELECT
  COUNT(*) AS n,
  AVG(price) AS mean,
  PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY price) AS median,
  MODE() WITHIN GROUP (ORDER BY price) AS mode,
  STDDEV(price) AS std_dev,
  MIN(price) AS min,
  MAX(price) AS max,
  MAX(price) - MIN(price) AS range
FROM products;
```

### 外れ値検出（四分位数法）

```sql
WITH quartiles AS (
  SELECT
    PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY amount) AS q1,
    PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY amount) AS q3
  FROM orders
)
SELECT
  o.order_id,
  o.amount,
  q1,
  q3,
  q3 - q1 AS iqr,
  CASE
    WHEN o.amount < q1 - 1.5 * (q3 - q1) THEN 'Lower Outlier'
    WHEN o.amount > q3 + 1.5 * (q3 - q1) THEN 'Upper Outlier'
    ELSE 'Normal'
  END AS outlier_status
FROM orders o, quartiles
WHERE o.amount < q1 - 1.5 * (q3 - q1)
   OR o.amount > q3 + 1.5 * (q3 - q1);
```

## 4. データ可視化の原則

**Data-Ink Ratio:** 情報量 / インク使用量を最大化

```
良い例：
┌─────────────────┐
│ Sales by Month  │
│ ┌───┐           │
│ │███│ Jan: 100K │
│ │███│ Feb: 120K │
│ │███│ Mar: 110K │
│ └───┘           │
└─────────────────┘

避けるべき例：
┌──────────────────────────────────┐
│ ★ MONTHLY SALES ANALYSIS ★       │
│ 3D グラフ + 不要な装飾            │
│ ※凡例が複雑、色が多い            │
└──────────────────────────────────┘
```

### チャート選定の原則

| データ型 | 最適なチャート | 避けるべき |
|---------|--------------|----------|
| 時系列 | 折れ線グラフ | 円グラフ |
| カテゴリ比較 | 棒グラフ | 3D円グラフ |
| 部分と全体 | 積上棒グラフ | 複雑な円グラフ |
| 相関関係 | 散布図 | 折れ線グラフ |
| 分布 | ヒストグラム、箱ひげ図 | 円グラフ |

## 5. ダッシュボード設計とストーリーテリング

**ストーリーテリングの流れ:**
1. **What:** 何が起きたか（KPI数値）
2. **Why:** なぜか（トレンド・要因分析）
3. **Action:** 次にどうするか（推奨アクション）

```
┌─────────────────────────────────────────┐
│ 月間売上ダッシュボード                   │
├─────────────────────────────────────────┤
│ [KPI] 売上: ¥5.2M | 対前月比: +12%      │
│ [トレンド] 過去6ヶ月の売上推移           │
│ [詳細] カテゴリ別内訳 + 地域別ランキング  │
│ [推奨] 在庫確保、営業強化対象           │
└─────────────────────────────────────────┘
```

## 6. ダッシュボード改善（Before / After）

**Before（問題点）:**
- グラフが20個以上（情報過多）
- 目的が不明確（何を判断する？）
- 自動更新だが、レイテンシが2時間（古い）

**After（改善）:**
```
【改善1】 グラフ数を7個に削減
  - KPI 3個（売上、顧客数、利益率）
  - トレンド 2個（売上推移、コンバージョン）
  - ドリルダウン対応 2個（カテゴリ、地域）

【改善2】 更新頻度を向上
  - リアルタイム更新（30分ごと）
  - キャッシュで対応（Vercel ISR等）

【改善3】 ドリルダウン機能追加
  - 「西日本」クリック → 都道府県別に展開
  - 「2月」クリック → 週別・日別に展開
```

## 8. ディメンション・メジャーの設計

**ディメンション（Dimension）:** 分析軸（何で分ける？）
```
例：
- 時間（年、月、週、日）
- 地域（国、都道府県、市区町村）
- カテゴリ（商品分類）
- ユーザー属性（年齢層、購買頻度）
```

**メジャー（Measure）:** 集計値（何を計測？）
```
例：
- 合計売上
- 平均注文単価
- ユーザー数
- コンバージョン率
```

**Tableau での定義:**
```
ディメンションをドラッグ → 行/列
メジャーをドラッグ → 値

行: 地域、月
列: （なし）
値: 売上（SUM）
結果: 地域×月のマトリックス
```

## 9. ドリルダウンの実装

**ドリルダウン:** 粗い視点から細かい視点へ遷移

```javascript
// React での実装例
const [drillLevel, setDrillLevel] = useState('country');

const data = {
  country: { 'Japan': 1000, 'US': 800, 'China': 600 },
  prefecture: { 'Tokyo': 400, 'Osaka': 300, 'Kyoto': 150 },
  city: { 'Shinjuku': 200, 'Shibuya': 150, 'Minato': 50 }
};

const handleDrill = (region) => {
  if (drillLevel === 'country') {
    setDrillLevel('prefecture');
  } else if (drillLevel === 'prefecture') {
    setDrillLevel('city');
  }
};

return (
  <BarChart data={data[drillLevel]} onClick={handleDrill} />
);
```
