# AM. データ設計

## 概要

データ設計は、ビジネスロジックをデータ構造に落とし込むプロセスです。エンティティ・属性・リレーションシップを明確化し、状態遷移・制約を定義することで、データの整合性・一貫性を保証します。正規化とビジネスルールの反映を両立させることが重要です。

---

## 1. 論理モデリング

**エンティティと属性：**
- **エンティティ：** 「ユーザー」「商品」「注文」等、実世界のもの・こと
- **属性：** エンティティの性質（ユーザーの「名前」「メールアドレス」）
- **リレーションシップ：** エンティティ間の関係（ユーザーが複数の注文を持つ）

**多重度：** リレーションシップの数的関係
- 1:1（一対一）：1 つのユーザーは 1 つのプロフィール画像を持つ
- 1:N（一対多）：1 つのユーザーは複数の注文を持つ
- N:M（多対多）：1 つの商品は複数のカテゴリに属し、1 つのカテゴリには複数の商品

**ER 図作成：** 作図ツール（Lucidchart、Miro）で可視化

---

## 2. ビジネスルールの反映

**状態遷移の定義：** エンティティが取りうる状態の遷移を明確化
- 注文：「作成」→「確認」→「決済」→「発送」→「配達完了」
- 各状態でのバリデーション（「確認済み」の注文は金額変更不可等）

**アンチパターン：フラグ地獄**
```
// 悪い例：複数フラグで状態を表現
isApproved, isRejected, isPending, isCanceled

// 良い例：Enum で状態を定義
enum OrderStatus {
  PENDING = 'pending',
  APPROVED = 'approved',
  REJECTED = 'rejected',
  CANCELED = 'canceled'
}
```

**ステートマシン図：** 状態とイベント（遷移条件）を図示
```
[作成] --決済成功--> [決済済み] --発送--> [発送済み]
   ^                      |
   |                      +--キャンセル--> [キャンセル]
   +--キャンセル-----------(直接)
```

---

## 3. リレーション設計

**自己結合（Self-Join）：** エンティティが自身と関連を持つ場合
- 例：従業員テーブルで「上司」列が同じテーブルの別の行を参照

**ポリモーフィック関連：** 異なるタイプのエンティティに関連付ける場合
```
comments テーブル:
- commentable_type: 'Post' or 'Review'
- commentable_id: 1 or 1
```

**中間テーブル（Join Table）：** N:M 関係を実装
```
products: id, name
categories: id, name
product_categories: product_id, category_id
```

---

## 4. 正規化と最適化

**正規化のステップ：**
- **第1正規形（1NF）：** すべての属性値が単一値（リスト・配列ではない）
- **第2正規形（2NF）：** 非キー属性が主キーに完全関数従属（部分関数従属がない）
- **第3正規形（3NF）：** 非キー属性同士が関数従属（推移関数従属がない）

**非正規化（Denormalization）：** パフォーマンス向上のため、意図的に正規化ルールを破る
- トレードオフ：更新が複雑 ↔ 読み取りが高速

---

## 5. 制約と整合性

**外部キー制約：** 参照整合性を保証
```sql
CREATE TABLE orders (
  id INT PRIMARY KEY,
  user_id INT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**ユニーク制約：** 重複を防止（メールアドレスは一意）

**CHECK 制約：** ドメイン値を制限（年齢 >= 0）

**デフォルト値・自動採番：** ID の自動生成、作成日時の自動記録

---

## 6. 物理設計・DDL

**テーブル作成（DDL）：**
```sql
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE,
  name VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (role_id) REFERENCES roles(id)
);
```

**インデックス設計：** 検索が頻繁なカラムにインデックスを設定
- WHERE 句で使用される列
- JOIN の結合キー
- ORDER BY で使用される列

効果的なインデックスでクエリパフォーマンスを大幅に向上させます。
