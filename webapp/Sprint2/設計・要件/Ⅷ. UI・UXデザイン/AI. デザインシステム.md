# AI. デザインシステム

## 概要

デザインシステムは、再利用可能なコンポーネント・パターン・ガイドラインを統合した、UIデザイン・実装の規範です。Atomic Design の思想に基づいて、Atoms（基本単位）から Pages（完全なページ）まで段階的に構築し、Storybook で管理することで、チーム全体での一貫性と開発効率を実現します。

---

## 1. Atomic Design の原則

**5つの階層で UI を構築：**

**Atoms（原子）:** 最小単位のコンポーネント
- ボタン、入力フィールド、ラベル、アイコン
- 単独で機能する最小要素

**Molecules（分子）:** Atoms を組み合わせた単位
- 検索フォーム（ラベル + 入力フィールド + ボタン）
- フォームフィールド（ラベル + 入力 + エラーメッセージ）

**Organisms（有機体）:** Molecules を組み合わせた大きな構成要素
- ナビゲーションヘッダー（ロゴ + メニュー + ユーザー設定）
- 商品カード一覧

**Templates（テンプレート）:** Organisms を配置してページの骨組みを作成
- ランディングページテンプレート
- 商品詳細ページテンプレート

**Pages（ページ）:** Template に実データを流し込んだ完成形
- 実際に公開されるページ

---

## 2. ヘッドレス UI の概念

**ヘッドレスUIとは：** スタイル（見た目）を持たない、純粋に機能・ロジックに専念するコンポーネント

**メリット：**
- **再利用性向上：** 同じロジックを異なるスタイルで使用可能
- **実装の柔軟性：** CSS フレームワークの切り替えが容易
- **アクセシビリティ：** 機能に専念し、ARIA属性・キーボード操作が充実

**例：** Radix UI、Headless UI
- コンポーネント自体には CSS がない
- 親フレームワーク（Tailwind CSS 等）で見た目を定義

---

## 3. Storybook による管理

Storybook は、UI コンポーネントをカタログ化し、ドキュメント・テスト・デモを一元管理するツールです。

**Storybook のメリット：**
- **コンポーネント一覧表示：** すべてのコンポーネント・バリエーションを確認
- **ドキュメント自動生成：** Props・使用例・ベストプラクティスを記載
- **ビジュアルテスト：** 異なるブラウザ・デバイスでの表示を確認
- **チーム協業：** デザイナー・エンジニアが同じ「唯一の情報源」を参照

**構成例：**
```
Buttons
├─ Primary Button
│  ├─ Default State
│  ├─ Hover State
│  ├─ Disabled State
│  └─ Different Sizes
└─ Secondary Button
   └─ ...

Forms
├─ Text Input
├─ Checkbox
└─ Select Dropdown
```

## 4. アクセシビリティ対応

デザインシステムの構築時点で、アクセシビリティ標準（WCAG）に対応することが重要です。

**対応項目：**
- **色コントラスト：** テキストと背景の明度比が 4.5:1 以上
- **キーボード操作：** すべてのインタラクションが Tab キーで実行可能
- **ARIA属性：** `role`、`aria-label`、`aria-describedby` の適切な設定
- **フォーカス可視化：** フォーカス時に視覚的フィードバックを提供

**Storybook での検証：**
- Accessibility Add-on で自動的にアクセシビリティチェック
- キーボードナビゲーションのテスト
- スクリーンリーダー対応確認

## 5. デザイントークン の活用

デザインシステムの基本となる「トークン」（色・フォント・間隔・影）を定義し、一元管理します。

**トークン例：**
```
Color Tokens:
- Primary: #007BFF
- Success: #28A745
- Error: #DC3545

Typography Tokens:
- Heading1: 2rem, bold, family: 'Inter'
- Body: 1rem, regular, family: 'Inter'

Spacing Tokens:
- XS: 0.5rem
- S: 1rem
- M: 1.5rem
- L: 2rem
```

トークンを統一することで、チーム全体での一貫性を保ち、テーマ切り替え（ダークモード等）も容易に実現できます。

---

## 6. デザインシステムの更新・進化

デザインシステムは「一度作ったら終わり」ではなく、プロダクト成長に合わせて進化させます。

**更新フロー：**
1. 新しいコンポーネント要件の発生
2. パターン化の判定（「これは他の場面でも使用するか」）
3. Storybook に追加
4. 既存ページのリファクタリング検討
5. チーム全体への通知
