# AJ. アクセシビリティ

## 概要

アクセシビリティとは、すべてのユーザー（障害の有無を問わず、高齢者・初心者を含む）が、平等にプロダクトを利用できる状態を実現することです。WCAG 2.1 ガイドラインに準拠し、インタラクティブ要素・フォーカス・入力手段を設計することで、より多くのユーザーへのサービス提供が可能になります。

---

## 1. インタラクティブ要素のアクセシビリティ

**キーボード操作対応：** すべてのインタラクティブ要素が、マウスを使わずキーボード（Tab、Enter、矢印キー等）のみで操作可能

- ボタンクリック → Enter / Space で実行
- メニュー選択 → 矢印キーで移動、Enter で決定
- テキスト入力 → Tab で次フィールドへ遷移

**フォーカス順序の設計：** Tab キーで移動する要素の順序が、ページの論理的な流れと一致していることが重要
- 悪い例：ページ右側 → 左側 → 中央（テレビの画面順）
- 良い例：上から下へ、左から右へ（読み順と同じ）

**スキップリンク：** ナビゲーションメニューをスキップして、メインコンテンツへ直接ジャンプできるリンク
```html
<a href="#main-content" class="skip-link">本文へスキップ</a>
```

## 2. カスタムコンポーネントの操作性

標準 HTML 要素（`<button>`、`<input>`）ではなく、カスタムコンポーネントを使用する場合、ARIA 属性で機能を明示する必要があります。

**ARIA属性の活用：**
- `role="button"` → 要素がボタンのように機能することを示す
- `aria-label="検索"` → スクリーンリーダーに読み上げさせるテキスト
- `aria-describedby="error-message"` → 関連する詳細説明へのリンク

```html
<div role="button" tabindex="0" aria-label="削除">
  <img src="trash-icon.svg" alt="" />
</div>
```

## 3. 色彩・コントラスト設計

**色彩のみで情報を伝えない：** 色覚異常ユーザーでも内容が理解できるよう、色に加えて形状・テキスト・パターンで情報を区別

- 悪い例：赤線 = エラー、緑線 = 成功（色覚異常者には区別困難）
- 良い例：赤線 + エラーアイコン + テキスト「エラーが発生しました」

**コントラスト比：** WCAG AA レベル（4.5:1）以上が推奨
- 通常テキスト：4.5:1 以上
- 大きいテキスト（18pt 以上）：3:1 以上

測定ツール：Axe DevTools、WebAIM Contrast Checker

## 4. ペルソナスペクトラム・ユニバーサルデザイン

**ペルソナスペクトラム：** 障害を「特定の人だけの問題」ではなく、誰もが経験しうることとして捉える視点

例：
- 視覚障害 ← → 明るい環境で画面が見づらい
- 運動障害 ← → 片手でマウス操作しながら電話を持っている
- 聴覚障害 ← → 周囲が騒がしいオフィス環境

**ユニバーサルデザイン：** 最初から「すべてのユーザー」を想定して設計
- アクセシビリティ = 事後対応ではなく、設計段階から組み込む

---

## 5. 多様な入力手段のサポート

ユーザーは様々なデバイス・入力方法を使用するため、複数の操作方法をサポートする必要があります。

**対応する入力方法：**
- キーボード（Tab、矢印キー、Enter）
- マウス（クリック、ホバー）
- タッチ（タップ、スワイプ、ピンチ）
- 音声コマンド（一部ブラウザで対応）
- 専用デバイス（スティックキー等）

**タッチターゲットサイズ：** 最低 48px × 48px（WCAG が推奨）
- 誤操作を減らし、肉体的負荷を軽減

---

## 6. 読みやすい文章設計

**シンプルな言語の使用：** 専門用語を避け、分かりやすい表現を心がける
- 悪い例：「本要件を遵行する」
- 良い例：「この条件に従う」

**文構造の簡潔化：** 長文を短く、1文 1 意味を基本
- 悪い例：「ユーザーが、過去に購入した商品について、その詳細情報と購買履歴が表示される」
- 良い例：「過去の購入履歴が表示されます。商品の詳細情報を確認できます。」

**見出し・リスト活用：** 情報を視覚的に分割
- 見出しで内容を先読み可能
- リストで複数項目を整理
