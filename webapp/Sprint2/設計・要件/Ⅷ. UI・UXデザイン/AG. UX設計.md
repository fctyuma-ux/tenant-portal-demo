# AG. UX設計

## 概要

UX（ユーザーエクスペリエンス）設計は、ユーザーがプロダクトと関わる一連の経験を、可能な限り円滑で楽しいものにするプロセスです。タスクフロー・情報アーキテクチャ・インタラクション設計を段階的に定義し、プロトタイプで検証することで、ビジネスゴールとユーザーニーズの両立を実現します。

---

## 1. タスクフロー設計

ユーザーが実現したいゴールを達成するまでの経路を可視化し、最適化します。

**ハッピーパス：** 最も一般的で障害のないシナリオ
- 例：「ユーザーがログイン → 検索 → 商品選択 → 支払い → 完了」

**フロー図の作成：** ダイアグラムツール（Miro、Lucidchart）で各ステップ・判定・分岐を図示

```
ログイン画面
    ↓
認証成功? → NO → エラーメッセージ表示 → ログイン画面に戻る
    ↓ YES
ホーム画面表示
    ↓
検索条件入力
    ↓
検索実行 → 結果なし → 「該当なし」メッセージ
    ↓ 結果あり
商品一覧表示
```

**ステップ数の削減：** タスク達成に不要なステップ・入力項目を削除
- 例：「住所確認画面を省略し、自動入力に変更」 → ステップ数 -1

---

## 2. 情報アーキテクチャ（IA）

ユーザーが迷わないよう、情報を論理的・階層的に組織化します。

**IAの構成要素：**
- **カテゴリ分類：** 情報をどのようにグループ分けするか
- **ナビゲーション構造：** メインナビ・サイドナビ・パンくずリストの配置
- **検索機能：** キーワード検索の実装範囲

**カードソーティング：** ユーザー（5～10名）が、機能・コンテンツを付箋紙に書いて、自分たちの論理で分類
- オープン型：カテゴリを作らず、ユーザーが自由に分類
- クローズド型：事前に提示したカテゴリに、ユーザーがアイテムをソート

結果から「ユーザーの期待するカテゴリ」を発見し、IA設計に反映させます。

**サイトマップの作成：**
```
ホーム
├─ 商品一覧
│  ├─ カテゴリ別フィルター
│  └─ 検索結果
├─ マイページ
│  ├─ 注文履歴
│  └─ ウィッシュリスト
└─ 設定
   ├─ プロフィール
   └─ 支払い方法
```

---

## 3. ナビゲーション・フィードバック設計

ユーザーが「今どこにいるのか」「次に何ができるのか」を常に把握できるようにします。

**パンくずリスト：** 階層構造を示し、上位階層へのジャンプを可能に
- 例：「ホーム > 商品一覧 > 家電 > スマートフォン」

**アフォーダンスとシグニファイア：** ユーザーが直感的に「クリック可能」と判断できるビジュアルデザイン
- アフォーダンス：オブジェクトの性質（「ボタンである」という属性）
- シグニファイア：その属性を示すデザイン（色・形・影）

```
❌ テキスト「詳細を見る」（ボタンに見えない）
✓ 青いボタンに白テキスト「詳細を見る」（クリック可能と明示）
```

**フィードバックの即時性：** ユーザー操作に対し、視覚的・音声的フィードバックを即座に返す
- ボタンクリック → 色変更 + 読み込みスピナー表示
- フォーム送信エラー → エラーメッセージ表示 + 該当フィールドのハイライト

---

## 4. 状態変化・アニメーション

複雑なインタラクションを「動き」で直感的に理解させます。

**状態変化のアニメーション：** 遷移前後の状態を滑らかに繋ぐことで、ユーザーの心理的混乱を軽減

遷移なし：背景 → 突然ダイアログ出現 → 「何が起きた？」と混乱

アニメーション付き：背景フェードアウト + ダイアログフェードイン → ユーザーが認識しやすい

**ジェスチャーUI：** スマートフォン上での直感的操作
- スワイプ左右でページ遷移
- ピンチズームで拡大縮小
- ロングプレスでメニュー表示

---

## 5. プロトタイプ検証

UX設計を検証するために、タスクフロー・ナビゲーション・アニメーションを含むプロトタイプを作成し、ユーザーテストを実施します。

**テスト項目：**
- ユーザーが目的のページ・機能にたどり着けるか
- ナビゲーション・パンくずリストが有効に機能しているか
- アニメーションが「快適」と感じられるか（遅すぎる・速すぎない）

**改善サイクル：** テスト結果から課題を抽出 → フロー・IAを見直し → プロトタイプ修正 → 再テスト
