# AF. プロトタイピング

## 概要

プロトタイピングは、デザイン検証と要件確認のための段階的なアプローチです。低忠実度（ワイヤーフレーム）から高忠実度（実装に近い形）へ進み、各段階でステークホルダーとユーザーからフィードバックを得て、本実装前に課題を発見・改善します。プロトタイプはあくまで「検証ツール」であり、本実装ではありません。

---

## 1. ビジュアル階層

ユーザーが情報を効率的に理解できるよう、視覚的な優先度を明確にします。

**実装のポイント:**
- 最優先の要素（CTA ボタン等）を大きく、目立つ配置に配置
- 色の使い分け（背景、強調色、中立色）で情報の重要度を表現
- 空白（ホワイトスペース）を活用して視認性を向上
- フォントサイズ、太さで階層を表現

**検証項目:**
- 見た瞬間に目が止まる要素は正しいか
- 複数の情報源がある場合、読む順序は自然か
- カラーコントラストは十分か（背景とテキストの比率4.5:1以上推奨）

---

## 2. デザインシステムの適用

既存のデザインシステムに従うことで、一貫性のあるプロトタイプを作成します。

**適用範囲:**
- カラーパレット（定義済みの色のみを使用）
- タイポグラフィ（フォント種、サイズ、行間の統一）
- コンポーネントライブラリ（ボタン、入力フィールド等の既成部品）
- スペーシング規則（8px グリッドシステム等）

**効果:**
- デザイナーと開発者の間で認識のズレを減らす
- 本実装への移行が素早くなる
- チーム全体での品質基準の維持

---

## 3. Figma 等でのデザイン

デザインツール（Figma、Adobe XD、Sketch）を使用して、高忠実度のビジュアルを作成します。

**Figma での実装:**
- フレーム（Page）を複数ページとして管理
- コンポーネント化してワイヤーフレームの再利用性を向上
- バージョン管理でデザイン変更の履歴を保持
- プロトタイプ機能でページ遷移を実装

```
例：e コマースサイトのプロトタイプ
┌─ ホーム
├─ 商品一覧
│  └─ 商品詳細
│     └─ カート追加
└─ プロフィール
```

---

## 4. バリエーション作成

異なる状態（ホバー、フォーカス、エラー、ローディング）を考慮して、複数のバリエーションを作成します。

**主なバリエーション:**
- **正常状態：** デフォルトの表示
- **ホバー状態：** マウスが要素上にある時
- **フォーカス状態：** キーボード操作でフォーカスされている時
- **エラー状態：** バリデーションエラー等を表示
- **ローディング状態：** 処理中を示す状態
- **ディセーブル状態：** 操作不可の状態

**実装例（フォーム）:**
```
Input フィールド
├─ 空の状態（プレースホルダー表示）
├─ 入力中（キャレット表示）
├─ 入力完了（値表示）
├─ エラー（赤枠、エラーメッセージ）
└─ 成功（チェックマーク）
```

**マルチデバイス対応:**
- デスクトップ（1440px 以上）
- タブレット（768px）
- モバイル（375px）

各ブレークポイントで自然に見えるレイアウトを検証。

---

## 5. ユーザーテストの設計

プロトタイプの有効性を検証するため、実際のユーザーにテストを実施します。

**テスト実施フロー:**
1. テスト目的を明確化（「商品を検索して購入する」等）
2. ユーザーに具体的なタスクを提示
3. 操作中の行動を観察（迷い、質問、コメント）
4. 完了時間、成功率、改善点を記録

**観察ポイント:**
- タスク達成に要した時間
- どこで迷ったか（クリック数が多いか、ボタンが見つけられなか等）
- ユーザーの発言内容
- 修正がなければ達成できたか

---

## 6. 段階的な忠実度向上

忠実度を段階的に上げることで、段階ごとに検証を行います。

**段階1：ワイヤーフレーム（低忠実度）**
- ページ構造のみを可視化
- グレースケール、簡潔な図形
- 確認項目：レイアウト、要素配置、情報構造

**段階2：モックアップ（中忠実度）**
- 色、フォント、画像を追加
- ビジュアルデザインを確認
- 確認項目：色選択、タイポグラフィ、コントラスト

**段階3：プロトタイプ（高忠実度）**
- インタラクション、ページ遷移を実装
- ホバー、クリック時の挙動を再現
- ユーザーテスト可能なレベル

---

## 7. プロトタイピングのメリット

- **コスト削減：** 実装前に大きな設計失敗を防ぐ
- **チーム共通認識：** 営業、デザイン、開発の意見を統一
- **ユーザー検証：** 本実装前にユーザー要望を反映
- **フィードバックループ：** 短い反復サイクルで改善を加速
