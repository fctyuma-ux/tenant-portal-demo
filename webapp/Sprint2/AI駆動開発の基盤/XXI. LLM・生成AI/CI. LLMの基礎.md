# CI. LLMの基礎

## 概要

大規模言語モデル（LLM）の構造と基本的な仕組みを理解することは、AI駆動開発の土台となります。このセクションでは、Transformerアーキテクチャから始まり、トークン化、コンテキストウィンドウなどの基本概念、そしてAPIを通じた実装までを学びます。各パラメータ（temperature、max_tokens等）の役割を理解し、モデル選択の判断軸を身につけることが目標です。

---

## 1. Transformer と Attention 機構

**Transformerの基本構造:**
- Query, Key, Value による attention 計算で「どの部分に注意すべきか」を動的に判定
- Multi-Head Attention により複数の観点から並列に関係性を捉える
- Positional Encoding によって単語の位置情報を保持

**Attentionの効果:**
- テキスト全体を並列処理できるため、RNNより効率的
- 長距離依存関係の学習が容易
- 可視化することで「モデルが何に注目しているか」の理解が進む

---

## 2. トークン化（Tokenization）

**トークンとは:**
- テキストを小分けにした最小単位（単語の一部、単語、あるいは複数単語で構成）
- モデル入力の基本単位であり、API料金計算の対象
- 言語やキャラクタセットで分割ルールが異なる

**実装上の注意:**
- 入力テキストの文字数 ≠ トークン数（言語に依存）
- 日本語は効率が悪い傾向（1単語が複数トークンに分割される）
- token counting APIで事前に確認可能

---

## 3. コンテキストウィンドウ（Context Window）

**定義:**
- モデルが処理可能な最大トークン数（入力+出力）
- 例：Claude 3 Haiku は 200K トークン

**実運用上の意味:**
- 長文ドキュメント処理時は分割戦略が必要
- コンテキストが大きいほど複雑なタスクに対応可能だが、遅延が増加
- キャッシング機能（Prompt Caching等）で同一部分の再利用効率化

---

## 4. Temperature と Top-p：パラメータ制御

**Temperature（0.0～2.0）:**
- 0.0 に近い：確定的、同じ入力で同じ出力
- 1.0：バランス型
- 2.0 に近い：多様性重視、創造的だが不安定

**用途別使い分け:**
- 要約・分類：temperature 低め（0.1～0.3）
- 創作・ブレストミーティング：temperature 高め（1.0～1.5）
- チャットボット：中程度（0.7～0.8）

**Top-p (Nucleus Sampling):**
- 累積確率が p を超えるまでの候補から選択
- temperature との組み合わせで精密な出力制御が可能

---

## 5. ファインチューニング vs RAG

**ファインチューニング:**
- 専門知識をモデル自体に組み込む
- 高コスト・時間がかかる
- ドメイン特化タスクに向く

**RAG（検索拡張生成）:**
- 外部ナレッジベース検索結果を入力に加える
- 低コスト・リアルタイム更新可能
- 最新情報や参照ベースの生成に向く

**選択基準:**
- データ量少ない、リアルタイム更新不要 → ファインチューニング
- データ量多い、更新頻繁、参照性重視 → RAG

---

## 6. モデルサイズと性能・コストの関係

**モデルサイズの影響:**
| サイズ | 処理速度 | 精度 | コスト | 用途 |
|-------|--------|------|--------|------|
| Haiku（小） | 高速 | 基本的 | 低 | シンプルタスク |
| Sonnet（中） | 中程度 | 高い | 中 | バランス型 |
| Opus（大） | 低速 | 最高 | 高 | 複雑推論 |

**コスト最適化:**
- 同一タスクで複数モデルのコスト・精度を比較
- 小さいモデルで十分なタスクはそちらを使う

---

## 7. Embedding とベクトル表現

**Embeddingの役割:**
- テキストを高次元ベクトル空間に変換
- 意味的に近いテキストは空間上でも近い
- セマンティック検索の基礎

**実装例:**

```python
import anthropic

client = anthropic.Anthropic()

# テキストをベクトル化
text = "猫は可愛い動物です"
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[{"role": "user", "content": text}]
)
# 実際のEmbedding APIはOpenAIやAnthropic等の専用APIを使用
```

## 8. マルチモーダル LLM

**対応形式:**
- テキスト＋画像：OCR、図表解析、スクリーンショット処理
- テキスト＋音声：音声認識結果の処理
- テキスト＋ビデオ：フレーム抽出による動画解析

**実装上の注意:**
- 画像はBase64エンコードまたはURL指定
- 形式・サイズ制限あり
- マルチモーダルは処理コスト高い傾向

---

## 9. 蒸留（Distillation）と量子化（Quantization）

**蒸留：**
- 大規模モデルの知識を小規模モデルに転送
- 推論速度向上、リソース削減
- 精度は若干低下することがある

**量子化：**
- 重み値を低精度で表現（float32 → int8等）
- メモリ削減、推論高速化
- オンプレミス・エッジデバイス向け

---

## 10. ローカル LLM と API の使い分け

**ローカルLLM（Ollama等）:**
- プライバシー重視、オフライン実行可能
- ハードウェア要件高い
- 小～中規模データ処理に向く

**APIベース（OpenAI/Anthropic等）:**
- 最新モデルへのアクセス
- スケーラビリティ高い
- コスト・セキュリティトレードオフ

**プラットフォーム比較:**
- OpenAI：パイオニア、豊富なモデル選択肢
- Anthropic Claude：安全性重視、長コンテキスト対応
- Google Gemini：マルチモーダル強み

---

## 11. APIキー管理とレート制限

**セキュリティ:**
- 環境変数（.env）で管理、リポジトリに含めない
- ローテーション、権限スコープ設定
- 定期的な監査

**レート制限対応:**
- エクスポーネンシャルバックオフによるリトライ
- キューイング・バッチ処理
- ユーザーごとの制限設定

---

## コード例：基本的なAPI呼び出し

```python
import anthropic
import os

client = anthropic.Anthropic(api_key=os.environ.get("ANTHROPIC_API_KEY"))

# 基本的な呼び出し
message = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    temperature=0.7,
    messages=[
        {"role": "user", "content": "LLMの仕組みを簡潔に説明してください"}
    ]
)
print(message.content[0].text)

# パラメータ制御の例
creative_response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    temperature=1.5,  # 創造的に
    top_p=0.9,        # 多様性重視
    messages=[
        {"role": "user", "content": "AIの未来について想像力豊かに述べてください"}
    ]
)
print(creative_response.content[0].text)
```
