# Input / Process / Output 一覧

> 全機能のデータフローを俯瞰し、機能間のデータ受け渡しを明確化する統合IPOマトリクス

## IPO 一覧

### P001: ログイン画面

| # | 機能 | Input | Process | Output | Output先 |
|---|------|-------|---------|--------|----------|
| 1 | メール・パスワード認証 | メールアドレス, パスワード | Supabase Authに認証リクエスト送信。成功時にセッショントークン取得 | セッション確立 / エラーメッセージ | → #2 Role判定 |
| 2 | Role判定 | セッショントークン（←#1） | ユーザーテーブルからuser_idに対応するroleカラムを取得 | role値（manufacturing / design / admin） | → #3 リダイレクト |
| 3 | Role別リダイレクト | role値（←#2） | roleに応じて遷移先URLを決定 | 製造→P002 / 設計→P004 / 管理者→P007 | → P002, P004, P007 |
| 4 | エラー表示 | Supabase Authエラーレスポンス（←#1失敗時） | エラーコードに応じたメッセージ生成 | エラーメッセージ文字列 | （画面内表示） |

### P002: 製造ダッシュボード＆報告画面

| # | 機能 | Input | Process | Output | Output先 |
|---|------|-------|---------|--------|----------|
| 5 | トラブル報告起票 | 設備名（選択）, ライン名（選択）, 現象テキスト（自由記述）, エラーコード（任意）, 停止時間_分 | バリデーション（設備名・ライン名・現象テキスト・停止時間は必須） | バリデーション通過: 送信可能状態 / エラー: メッセージ | → #8 報告送信 |
| 6 | RAGリアルタイムサジェスト | 現象テキスト（入力中、デバウンス500ms） | テキストをベクトル化しFAISSにセマンティック検索（internal_idで検索→trouble_reportsにJOIN）。類似度上位5件取得 | 類似トラブルリスト（現象・解決策・類似度スコア） | （画面内サジェスト表示） |
| 7 | Charge-back累計表示 | ログインユーザーID, 当月期間 | Charge-backテーブルから当月の成功レコードをSUM | 累計金額（¥表示） | （画面内カード表示） |
| 8 | 報告送信 | フォームデータ（←#5） | トラブルレポートをDB保存、AI解析ジョブをキュー投入 | トラブルレポートID | → P003（#10,#11,#12） |
| 9 | 過去報告一覧 | ログインユーザーID | 自分が起票したトラブル報告を日時降順で取得（直近20件） | 報告リスト（日時・設備名・ステータス・損失額） | → P003（行クリック時） |

### P003: AI解析結果・Charge-back確認画面

| # | 機能 | Input | Process | Output | Output先 |
|---|------|-------|---------|--------|----------|
| 10 | AI構造化データ表示 | トラブルレポートID（←P002 #8） | AI解析結果をDBから取得。NLPで分類、部品マスタ照合、過去DB類似度検索 | 構造化データ（現象カテゴリ, 推定原因, 関連部品名, 過去類似件数） | → #13 Charge-back（データの一部） |
| 11 | 総損失額プレビュー | 停止時間_分, ライン名（←P002 #8のレポート経由） | ラインマスタからライン別単価（¥/分）取得。機会損失 = 停止時間 × 単価 | 損失額内訳（直接費 + 機会損失 = 総損失額） | → #13 Charge-back（総損失額） |
| 12 | 責任判定表示 | トラブルレポートID, AI解析結果（←#10） | 過去の類似トラブルの発生パターン・頻度・構造的要因をAI分析し設計起因度（0〜100%）算出 | 設計起因度（%）, 判定根拠テキスト | → #13 Charge-back（起因度） |
| 13 | Charge-back実行 | トラブルレポートID, 総損失額（←#11）, 設計起因度（←#12） | Charge-backレコードをDB作成（金額 = 総損失額 × 起因度/100）。即時反映 | DB: Charge-backレコード | → P002 #7（累計更新）, P004 #15,#16,#19（損失反映） |
| 14 | 報告の修正 | 修正後の構造化データ | AI解析結果を上書き更新。損失額・責任判定を再計算 | 更新された構造化データ・損失額・責任判定 | → #10,#11,#12（再表示） |

### P005: トラブル詳細・対策実行画面（統合画面）

| # | 機能 | Input | Process | Output | Output先 |
|---|------|-------|---------|--------|----------|
| 20 | AI分析詳細表示 | 設備ID/部品ID（←P004 #18） | 全トラブルレポートのAI解析結果を集約。頻出原因パターン・キーワード抽出 | AI分析サマリー（主要原因パターン, 頻出キーワード, 設計起因割合） | （画面内表示） |
| 21 | トラブル履歴一覧 | 設備ID/部品ID（←P004 #18） | 該当設備・部品のトラブルレポートを日時降順取得 | 履歴リスト（日時, 現象, 損失額, 対応内容, ステータス） | （画面内テーブル表示） |
| 22 | ROIシミュレーション（数値算出） | 対策コスト（ユーザー入力¥）, 設備ID/部品ID | 【Deterministic】過去の発生頻度×平均損失額を年換算し予測損失額算出。回収期間 = 対策コスト ÷ 年間予測損失額 | 予測年間損失額, 回収期間（月）, 投資対効果比率 | → #23 AI提案文（ROI数値） |
| 23 | AI投資提案文の自動生成 | ROI数値（←#22）, RAGの類似トラブルテキスト群（←ベクトルDB） | 【AI-Driven】ROI数値＋RAGテキスト群をLLMプロンプトに渡し提案文生成: (1)技術的背景 (2)経営的リスク (3)推奨アクション | AI生成の投資提案文（マークダウン形式） | → #26 レポート出力 |
| 24 | 対策ステータス更新 | 新ステータス（未対応/対応中/完了）, 設備ID/部品ID | DBの対策ステータスを更新 | 更新成功: ステータス更新 / 失敗: エラー | → #25（完了時に通知トリガー） |
| 25 | 現場自動通知 | ステータス=「完了」（←#24）, 関連報告者ID一覧 | 該当設備・部品のトラブル報告者全員にアプリ内通知作成 | 通知レコード | → P002（報告者の画面に表示） |
| 26 | ROI分析レポート出力 | ROI数値（←#22）＋AI提案文（←#23） | @media printで印刷用レイアウトに変換 | ブラウザ印刷ダイアログ | （印刷出力） |

## 機能間データフロー図

### 製造部門フロー（田中）

```
P001 #1認証 → #2Role判定 → #3リダイレクト
                                  ↓ (manufacturing)
P002 #5起票 → #8送信 ──────────→ P003 #10AI構造化
     #6RAGサジェスト ←──── ベクトルDB        #11損失額計算 ←── ラインマスタ（単価）
     #7累計表示 ←────── Charge-backテーブル   #12責任判定
     #9過去報告 ←────── トラブルレポートDB     ↓
                                         #13 Charge-back実行
                                              ↓
                                    Charge-backテーブル書込
                                         ↓        ↓
                              P002 #7累計更新    P004へ即時反映
```

### 設計部門フロー（佐藤）

```
P001 #1認証 → #2Role判定 → #3リダイレクト
                                  ↓ (design)
P004 #15損失総額 ←── Charge-backテーブル
     #16ランキング ←── Charge-backテーブル
     #19新着通知 ←── Charge-backテーブル（is_read=FALSE AND is_historical=FALSE）
     #18詳細遷移 ──────────→ P005 #20AI分析詳細
                                    #21トラブル履歴
                                    #22ROI数値算出（Deterministic）
                                         ↓
                                    #23AI提案文生成（LLM）←── ベクトルDB（RAGテキスト）
                                         ↓
                                    #26レポート出力（印刷）
                                    #24ステータス更新
                                         ↓ (完了時)
                                    #25現場自動通知 → P002（田中へ通知）
```

### データ供給フロー（管理者）

```
P007 #35CSVアップロード（26カラム固定）
       ↓
     #36プレビュー（先頭10行確認）
       ↓
     #37AI構造化バッチ
       ├→ マスタテーブル（工場・ライン・設備・部品）upsert
       ├→ トラブルレポートテーブルINSERT（internal_id自動採番）
       ├→ LLM構造化（現象カテゴリ・推定原因・設計起因度）
       ├→ FAISS登録（キー: internal_id → RAG/セマンティック検索用）
       └→ Charge-back作成（is_historical=TRUE → 新着通知対象外）
              ↓
         全システムのデータ基盤として供給
         → P002 #6 RAGサジェスト
         → P003 #10 AI構造化, #12 責任判定
         → P005 #23 AI提案文生成
         → P006 #27 セマンティック検索, #28 キーワード検索
```

### 共通ナレッジ検索フロー

```
P006 #29モード切替 → #27セマンティック検索 ←── FAISS（internal_id→JOINで解決。P002 #6と共通基盤）
                    or #28キーワード検索  ←── トラブルレポートDB
       ↓
     #30フィルタ → #31一覧表示 → #33ナレッジ閲覧（モーダル）
     #34対策済みフィルタ ↗
     #32ソート ↗
```

## 共通データ基盤マトリクス

| データ基盤 | 書込元 | 読取先 |
|-----------|--------|--------|
| **ユーザーテーブル**（role含む） | 管理者が事前作成 | P001 #2 Role判定 |
| **設備マスタ** | P007 #37（upsert） | P002 #5（選択肢）, P003 #10（照合）, P004 #16（集計キー）, P005 #20（集約） |
| **ラインマスタ**（単価含む） | P007 #37（upsert） | P002 #5（選択肢）, P003 #11（単価取得）, P005 #22（ROI年換算） |
| **部品マスタ** | P007 #37（upsert） | P003 #10（照合）, P004 #16（集計キー） |
| **トラブルレポートテーブル** | P002 #8（新規）, P007 #37（バッチ） | P002 #9, P003 #10,#12, P005 #21, P006 #28,#31,#33 |
| **AI解析結果テーブル** | P003 #10（新規解析）, P007 #37（バッチ） | P003 #10,#12,#14, P005 #20, P006 #33 |
| **Charge-backテーブル** | P003 #13（新規作成）, P007 #37（バッチ作成、is_historical=TRUE） | P002 #7（累計）, P004 #15,#16（全件集計）, #19（is_historical=FALSEのみ） |
| **FAISS**（Embedding） | P007 #37（バッチ登録、キー: internal_id）, P002 #8→AI解析時に登録 | P002 #6（RAG、internal_id→JOIN）, P005 #23（RAGテキスト取得）, P006 #27（セマンティック検索、internal_id→JOIN） |
| **通知テーブル** | P005 #25（対策完了通知） | P002（報告者の画面に表示） |
| **インポートジョブテーブル** | P007 #37（ジョブ作成） | P007 #38（進捗）, #39（結果） |
