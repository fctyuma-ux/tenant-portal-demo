# 要件定義書 v2: ログイン画面（P001）

> DB設計を踏まえた要件定義書の更新

## 目的

メールアドレスとパスワードによるユーザー認証を行い、DBのroleカラムに基づいてRole（製造/設計/管理者）を判定し、対応するダッシュボードへ振り分ける。サインアップ機能は不要（管理者が事前にアカウント作成）。

## 機能

| # | 機能 | 説明 | DB関連テーブル |
|---|------|------|--------------|
| 1 | メール・パスワード認証 | Supabase Authを使ったメールアドレス＋パスワードによるログイン | Supabase Auth（外部） |
| 2 | Role判定 | 認証成功後、DBのユーザーテーブルのroleカラムからRole（製造/設計/管理者）を取得 | `users` READ |
| 3 | Role別リダイレクト | 製造→P002、設計→P004、管理者→P007へ自動遷移 | ―（クライアント側ルーティング） |
| 4 | エラー表示 | 認証失敗時のエラーメッセージ表示（メール/パスワード不正、アカウント未登録等） | ―（クライアント側表示） |

## Input / Process / Output

| 機能 | Input | Process | Output | DB関連テーブル |
|------|-------|---------|--------|--------------|
| メール・パスワード認証 | メールアドレス、パスワード | Supabase Authに認証リクエストを送信。成功時にセッショントークンを取得 | 認証成功: セッション確立 / 認証失敗: エラーメッセージ | Supabase Auth（外部） |
| Role判定 | セッショントークン（認証済みユーザーID） | `users`テーブルからidに対応するroleカラムを取得 | role値（"manufacturing" / "design" / "admin"） | `users` READ |
| Role別リダイレクト | role値 | roleに応じて遷移先URLを決定 | 製造→/dashboard/manufacturing、設計→/dashboard/design、管理者→/admin/import | ― |
| エラー表示 | Supabase Authのエラーレスポンス | エラーコードに応じたメッセージを生成 | エラーメッセージ文字列の表示 | ― |

## UI状態遷移

| 要素 | 対応機能 | 状態 | DB関連テーブル |
|------|---------|------|--------------|
| メール入力フィールド | メール・パスワード認証 | 空 → 入力中 → バリデーションエラー（不正形式） | ― |
| パスワード入力フィールド | メール・パスワード認証 | 空 → 入力中 | ― |
| ログインボタン | メール・パスワード認証 | 無効（入力未完了）→ 有効（入力完了）→ ローディング（認証中）→ 有効（完了/失敗） | Supabase Auth → `users` |
| エラーメッセージ | エラー表示 | 非表示 → 表示（認証失敗時） | ― |
| 画面全体 | Role別リダイレクト | ログインフォーム表示 → ローディング → リダイレクト | `users.role` による分岐 |
