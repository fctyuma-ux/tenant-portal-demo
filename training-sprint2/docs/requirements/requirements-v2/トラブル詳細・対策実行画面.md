# 要件定義書 v2: トラブル詳細・対策実行画面 - 統合画面（P005）

> DB設計を踏まえた要件定義書の更新

## 目的

特定の設備・部品に関するAI分析の詳細を確認し、ROIシミュレーション（過去実績の年換算ベース）で対策の投資対効果を試算する。さらに、ROI数値＋RAGの類似トラブルテキスト群をLLMに渡し、投資実行の提案文（技術的背景・経営的リスク・推奨アクション）を自動生成する。数値算出はシステムロジック（Deterministic）、示唆出しはAI（AI-Driven Insight）というハイブリッド方式を採用。対策ステータスの更新と現場への自動通知まで、佐藤のPhase 2（分析）とPhase 3（対策実行）を1画面で完結させる。

## 機能

| # | 機能 | 説明 | DB関連テーブル |
|---|------|------|--------------|
| 1 | AI分析詳細表示 | 該当設備・部品に関する過去全トラブルのAI分析結果を集約表示 | `trouble_reports` READ, `ai_analyses` READ, `equipment` READ, `parts` READ |
| 2 | トラブル履歴一覧 | この設備・部品に関する過去のトラブル発生履歴をリスト表示 | `trouble_reports` READ, `ai_analyses` READ |
| 3 | ROIシミュレーション（数値算出） | 過去実績の年換算で予測損失額をシステムロジックで堅実に計算（Deterministic）。対策コスト vs 予測損失額を比較し回収期間を算出 | `trouble_reports` READ, `ai_analyses` READ, `countermeasures` UPSERT |
| 4 | AI投資提案文の自動生成 | ROI数値＋RAGの類似トラブルテキスト群をLLMに渡し、投資実行の提案文を自動生成 | FAISS READ, `countermeasures` UPDATE（investment_proposal_text） |
| 5 | 対策ステータス更新 | 未対応 / 対応中 / 完了（Fixed）のステータスを変更 | `countermeasures` UPDATE |
| 6 | 現場自動通知 | ステータスを「完了」に変更した際、関連トラブル報告者へ自動通知 | `notifications` INSERT, `trouble_reports` READ |
| 7 | ROI分析レポート出力 | ROI数値＋AI提案文を画面印刷（CSS制御）で上司への決裁資料として出力 | ―（@media print、クライアント側） |

## Input / Process / Output

| 機能 | Input | Process | Output | DB関連テーブル |
|------|-------|---------|--------|--------------|
| AI分析詳細表示 | 設備ID/部品ID（P004から遷移時に取得） | `trouble_reports`テーブルからequipment_id/part_codeで全レポート取得。`ai_analyses`とJOINしてAI解析結果を集約。頻出symptom_category・estimated_root_causeを抽出 | AI分析サマリー（主要原因パターン、頻出キーワード、設計起因割合） | `trouble_reports` READ, `ai_analyses` READ, `equipment` READ, `parts` READ |
| トラブル履歴一覧 | 設備ID/部品ID | `trouble_reports`テーブルからequipment_id/part_codeで日時降順取得。`ai_analyses`とJOIN | トラブル履歴リスト（occurred_at, description_symptom, total_loss_yen, description_treatment, status） | `trouble_reports` READ, `ai_analyses` READ |
| ROIシミュレーション（数値算出） | 対策コスト（ユーザー入力、¥）、設備ID/部品ID | 【Deterministic】`trouble_reports`+`ai_analyses`から過去の発生頻度×平均total_loss_yenを年換算して予測損失額算出。回収期間=対策コスト÷年間予測損失額。結果を`countermeasures`テーブルにUPSERT | 予測年間損失額、回収期間（月）、投資対効果比率 | `trouble_reports` READ, `ai_analyses` READ, `countermeasures` UPSERT |
| AI投資提案文の自動生成 | ROI数値（predicted_annual_loss_yen・payback_period_months）、RAGから取得した類似トラブルテキスト群 | 【AI-Driven】FAISSから類似テキスト取得（internal_id→JOINで本文取得）。ROI数値＋テキスト群をLLMに渡し提案文生成。結果を`countermeasures.investment_proposal_text`にUPDATE | AI生成の投資提案文（マークダウン形式） | FAISS READ → `trouble_reports` JOIN, `countermeasures` UPDATE |
| 対策ステータス更新 | 新ステータス（未対応/対応中/完了）、設備ID/部品ID | `countermeasures`テーブルのstatusカラムをUPDATE。「完了」の場合は通知トリガーも発火 | 更新成功: ステータス表示の更新 / 失敗: エラーメッセージ | `countermeasures` UPDATE |
| 現場自動通知 | ステータス=「完了」、関連報告者ID一覧 | `trouble_reports`テーブルからequipment_id/part_codeで報告者（reported_by）一覧取得。`notifications`テーブルにINSERT（ユーザー毎） | 通知レコードの作成（報告者のP002に表示される） | `notifications` INSERT, `trouble_reports` READ |
| ROI分析レポート出力 | ― | 画面を印刷用レイアウトに変換（@media print）。ROI数値＋AI提案文を含むレイアウト | ブラウザの印刷ダイアログを表示 | ―（クライアント側表示のみ） |

## UI状態遷移

| 要素 | 対応機能 | 状態 | DB関連テーブル |
|------|---------|------|--------------|
| 設備・部品ヘッダー | AI分析詳細表示 | ローディング → 表示（設備名・部品名・累積損失額） | `equipment` READ, `parts` READ, `chargebacks` READ |
| AI分析サマリーカード | AI分析詳細表示 | ローディング → 結果表示（原因パターン・キーワード） | `ai_analyses` READ |
| トラブル履歴テーブル | トラブル履歴一覧 | ローディング → リスト表示 → 行クリックでモーダル展開 | `trouble_reports` READ |
| 対策コスト入力フィールド | ROIシミュレーション（数値算出） | 空 → 入力中 → 入力確定（自動計算発火） | ― |
| ROI結果パネル | ROIシミュレーション（数値算出） | 非表示（未入力）→ 計算中 → 結果表示（予測損失額・回収期間・効果比率） | `countermeasures` UPSERT |
| 提案文生成ボタン | AI投資提案文の自動生成 | 無効（ROI未算出）→ 有効（ROI算出済み）→ ローディング（LLM生成中） | FAISS READ |
| AI提案文パネル | AI投資提案文の自動生成 | 非表示 → ローディング（LLM生成中）→ 提案文表示（技術的背景・経営的リスク・推奨アクション） | `countermeasures` UPDATE |
| 対策ステータスセレクト | 対策ステータス更新 | 未対応（デフォルト）→ 対応中 → 完了 ※変更時に確認ダイアログ表示 | `countermeasures` UPDATE |
| レポート出力ボタン | ROI分析レポート出力 | 無効（提案文未生成）→ 有効（提案文生成済み）→ クリックでブラウザ印刷ダイアログ表示 | ― |
