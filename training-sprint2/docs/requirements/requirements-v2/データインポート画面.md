# 要件定義書 v2: データインポート画面 - バックオフィス（P007）

> DB設計を踏まえた要件定義書の更新

## 目的

管理者が過去に蓄積されたトラブルデータ（固定フォーマットCSV）を一括でDBに取り込み、AIによる構造化処理をバッチ実行する。LLMの処理時間（1件あたり数秒）を考慮し、FastAPI BackgroundTasksによる簡易非同期処理＋フロントエンドからのポーリングで進捗を表示する。

## 機能

| # | 機能 | 説明 | DB関連テーブル |
|---|------|------|--------------|
| 1 | CSVファイルアップロード | 固定フォーマットの過去トラブルデータCSVをアップロード。カラムマッピングは不要 | ―（クライアント側パース） |
| 2 | データプレビュー | アップロードCSVの先頭数行をプレビュー表示し、フォーマット適合を確認 | ―（クライアント側表示） |
| 3 | AI構造化バッチ実行 | 全レコードに対してLLMで構造化処理（現象/原因分類・損失額計算）をバッチ実行。FastAPI BackgroundTasksで非同期処理 | `factories` UPSERT, `lines` UPSERT, `equipment` UPSERT, `parts` UPSERT, `products` UPSERT, `trouble_reports` INSERT, `ai_analyses` INSERT, `chargebacks` INSERT（is_historical=TRUE）, `import_jobs` INSERT/UPDATE, `import_records` INSERT/UPDATE, FAISS WRITE |
| 4 | 処理進捗ポーリング | フロントエンドから数秒ごとに進捗APIをポーリングし、プログレスバーを更新 | `import_jobs` READ |
| 5 | インポート結果確認 | 処理完了後の結果サマリー（成功件数・エラー件数・エラー詳細） | `import_jobs` READ, `import_records` READ |

## Input / Process / Output

| 機能 | Input | Process | Output | DB関連テーブル |
|------|-------|---------|--------|--------------|
| CSVファイルアップロード | CSVファイル（固定フォーマット: record_id, 発生日時, 完了日時, 工場, ラインID, ライン名, 設備ID, 設備名, 設備メーカー, 導入年, 製品カテゴリ, 対象製品, 型番, トラブル区分, 停止時間_分, 生産影響, 担当者コード, 部品コード, 交換部品名, 部品費_円, 外注費_円, 合計コスト_円, 現象記述, 原因記述, 処置記述, 備考_引継ぎ） | ファイルサイズ・拡張子のバリデーション。CSVパースしヘッダー行の26カラム名を固定フォーマットと照合 | フォーマット適合: プレビュー表示 / 不適合: エラーメッセージ（不足カラム名を明示） | ―（クライアント側） |
| データプレビュー | パース済みCSVデータ | 先頭10行を表示用に整形。総行数（インポート対象件数）を算出 | プレビューテーブル（先頭10行）、総件数表示 | ― |
| AI構造化バッチ実行 | インポート対象の全レコード（26カラム） | (1) `import_jobs`にINSERT（status=pending）。(2) CSVの各行をパースし、マスタデータを各テーブルにupsert（`factories`, `lines`, `equipment`, `parts`, `products`）。(3) `trouble_reports`にINSERT（internal_id自動採番）。`import_records`にINSERT。(4) BackgroundTasksで1件ずつLLM構造化→`ai_analyses`にINSERT。(5) 結果＋元テキストをベクトル化→FAISS登録（キー: internal_id）。(6) `chargebacks`にINSERT（is_historical=TRUE、新着通知対象外）。(7) `import_records`・`import_jobs`のステータス更新 | ジョブID（進捗ポーリング用） | `factories` UPSERT, `lines` UPSERT, `equipment` UPSERT, `parts` UPSERT, `products` UPSERT, `trouble_reports` INSERT, `ai_analyses` INSERT, `chargebacks` INSERT, `import_jobs` INSERT/UPDATE, `import_records` INSERT/UPDATE, FAISS WRITE |
| 処理進捗ポーリング | ジョブID | `import_jobs`テーブルからstatus, processed_count, total_count, error_countを取得。3秒間隔でフロントからポーリング | 進捗率（%）、処理済み件数、エラー件数、完了フラグ | `import_jobs` READ |
| インポート結果確認 | ジョブID（完了後） | `import_jobs`テーブルから最終結果取得。`import_records`テーブルからstatus=errorのレコードを取得しerror_detailとrow_numberを表示 | 結果サマリー（成功件数・エラー件数）、エラー詳細リスト（行番号・エラー内容） | `import_jobs` READ, `import_records` READ |

## UI状態遷移

| 要素 | 対応機能 | 状態 | DB関連テーブル |
|------|---------|------|--------------|
| CSVアップロードエリア | CSVファイルアップロード | 待機（ドラッグ&ドロップ可）→ ファイル選択済み（ファイル名表示）→ バリデーション中 → 成功（プレビュー表示）/ エラー（フォーマット不適合メッセージ） | ― |
| データプレビューテーブル | データプレビュー | 非表示 → 表示（先頭10行＋総件数） | ― |
| インポート実行ボタン | AI構造化バッチ実行 | 非表示（未アップロード）→ 有効（プレビュー表示後）→ 無効（処理中）→ 非表示（完了後） | `import_jobs` INSERT |
| プログレスバー | 処理進捗ポーリング | 非表示 → 表示（0%）→ 進行中（n%、3秒ごとに更新）→ 完了（100%） | `import_jobs` READ |
| 処理件数カウンター | 処理進捗ポーリング | 非表示 → 「処理中: X / Y 件（エラー: Z 件）」 | `import_jobs` READ |
| 処理結果サマリー | インポート結果確認 | 非表示 → 表示（成功件数・エラー件数） | `import_jobs` READ |
| エラー詳細リスト | インポート結果確認 | 非表示 → 表示（エラーがある場合のみ。行番号＋エラー内容のリスト） | `import_records` READ |
