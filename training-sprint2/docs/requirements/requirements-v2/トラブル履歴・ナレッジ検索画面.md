# 要件定義書 v2: トラブル履歴・ナレッジ検索画面（P006）

> DB設計を踏まえた要件定義書の更新

## 目的

製造・設計の両部門が、過去の全構造化トラブルデータを検索・閲覧し、解決済みナレッジを活用する。検索はハイブリッド方式（セマンティック検索＋キーワード検索）をトグルで切り替え、表記揺れの吸収と正確なファクト抽出を両立する。

## 機能

| # | 機能 | 説明 | DB関連テーブル |
|---|------|------|--------------|
| 1 | セマンティック検索 | 自然言語による意味ベースの検索。表記揺れを吸収し類似トラブルを網羅検索。P002のRAG検索エンジンと共通基盤 | FAISS READ → `trouble_reports` JOIN（internal_id）, `ai_analyses` READ |
| 2 | キーワード検索 | エラーコード・部品型番などのピンポイント検索。完全一致・部分一致によるファクト抽出 | `trouble_reports` READ（pg_trgm LIKE）, `ai_analyses` READ |
| 3 | 検索モード切り替え | 「自然言語検索」と「型番/コード検索」のトグルボタンで切り替え | ―（クライアント側状態） |
| 4 | フィルタ絞り込み | 設備名・部品名・期間・ステータス・原因区分での絞り込み | `equipment` READ, `parts` READ（フィルタ選択肢） |
| 5 | トラブル履歴一覧表示 | 検索結果を一覧テーブルで表示（ページネーション付き） | `trouble_reports` READ, `ai_analyses` READ, `equipment` READ |
| 6 | ソート | 日時・損失額・設備名などでソート切り替え | ―（クエリ ORDER BY 変更） |
| 7 | ナレッジ閲覧 | トラブルの詳細情報・解決策・対策内容をモーダルで表示 | `trouble_reports` READ, `ai_analyses` READ, `chargebacks` READ, `countermeasures` READ |
| 8 | 対策済みフィルタ | 対策完了済みのナレッジのみを表示するトグル | ―（クエリ WHERE 条件追加） |

## Input / Process / Output

| 機能 | Input | Process | Output | DB関連テーブル |
|------|-------|---------|--------|--------------|
| セマンティック検索 | 自然言語テキスト（例: 「溶接ロボットのアームが止まる」） | 入力テキストをベクトル化し、FAISSにセマンティック検索（internal_idで検索→`trouble_reports`にJOIN。P002 #6のRAGと共通基盤）。`ai_analyses`ともJOINして構造化データ取得 | 類似トラブルのリスト（類似度スコア付き） | FAISS READ → `trouble_reports` JOIN（internal_id）, `ai_analyses` READ |
| キーワード検索 | キーワード文字列（例: 「E-401」「PRT-015」） | `trouble_reports`テーブルに対してLIKE検索（pg_trgmインデックス使用）。error_code, part_code, description_symptomカラムを横断検索 | マッチしたトラブルのリスト | `trouble_reports` READ（pg_trgm）, `ai_analyses` READ |
| 検索モード切り替え | トグルの選択状態（自然言語 / 型番・コード） | 選択されたモードに応じて検索エンジンを切り替え。検索窓のプレースホルダーもモードに応じて変更 | 検索モードの状態変更、プレースホルダー更新 | ― |
| フィルタ絞り込み | 設備名（選択）、部品名（選択）、期間（開始日・終了日）、ステータス（選択）、原因区分（選択） | `equipment`・`parts`テーブルからフィルタ選択肢を取得。検索結果に対してWHERE条件をANDで追加適用 | フィルタ適用後の結果リスト | `equipment` READ, `parts` READ |
| トラブル履歴一覧表示 | 検索結果データ、ページ番号 | `trouble_reports`と`ai_analyses`をJOIN。`equipment`テーブルともJOINして設備名取得。1ページ20件でOFFSET/LIMIT | テーブル表示（occurred_at, equipment.name, description_symptom, total_loss_yen, status） | `trouble_reports` READ, `ai_analyses` READ, `equipment` READ |
| ソート | ソートキー（日時/損失額/設備名）、ソート順（昇順/降順） | ORDER BY句を動的に構築して再クエリ | ソート済みリストの再表示 | `trouble_reports` READ |
| ナレッジ閲覧 | トラブルレポートID（行クリック） | `trouble_reports`からreport_idで全詳細取得。`ai_analyses`, `chargebacks`, `countermeasures`をそれぞれJOIN | モーダルに詳細情報を表示（AI構造化データ・損失額・対策内容・ステータス） | `trouble_reports` READ, `ai_analyses` READ, `chargebacks` READ, `countermeasures` READ |
| 対策済みフィルタ | トグルのON/OFF | ONの場合、`trouble_reports.status='完了'`の条件を追加 | フィルタ適用後の結果リスト | `trouble_reports` READ |

## UI状態遷移

| 要素 | 対応機能 | 状態 | DB関連テーブル |
|------|---------|------|--------------|
| 検索モードトグル | 検索モード切り替え | 「自然言語検索」（デフォルト）↔「型番/コード検索」 | ― |
| 検索窓 | セマンティック検索 / キーワード検索 | 空（プレースホルダー: モード別に変化）→ 入力中 → Enter/検索ボタンで検索実行 | FAISS or `trouble_reports`（モード依存） |
| 検索窓プレースホルダー | 検索モード切り替え | 自然言語モード: 「トラブルの状況を入力...」/ 型番・コードモード: 「エラーコードや部品型番を入力...」 | ― |
| フィルタパネル | フィルタ絞り込み | 折りたたみ（デフォルト）→ 展開 → フィルタ選択中 → 適用済み（バッジ表示） | `equipment` READ, `parts` READ |
| トラブル履歴テーブル | トラブル履歴一覧表示 | 初期表示（全件）→ ローディング（検索中）→ 結果表示 → 結果なし表示 | `trouble_reports` READ |
| カラムヘッダー | ソート | 未ソート → 昇順（▲）→ 降順（▼）→ 未ソート（クリックで循環） | ― |
| ステータスバッジ | トラブル履歴一覧表示 | 未対応（赤）/ 対応中（黄）/ 完了（緑） | `trouble_reports.status` |
| 対策済みフィルタトグル | 対策済みフィルタ | OFF（全件表示）↔ ON（完了のみ表示） | ― |
| ナレッジ詳細モーダル | ナレッジ閲覧 | 非表示 → 表示（行クリック）→ 非表示（閉じるボタン） | `trouble_reports`, `ai_analyses`, `chargebacks`, `countermeasures` READ |
