# ペルソナ: 田中 守（Mamoru Tanaka）

> 「設計が悪いのに、なぜ俺たちの経費になるんだ。報告書を書いても何も変わらない。」

## ユーザー属性

| 項目 | 内容 |
|------|------|
| 名前 | 田中 守（Mamoru Tanaka） |
| 年齢 | 45歳 |
| 職業 | 保全課リーダー |
| 部門 | 大口工場 製造部 保全課 |
| 勤務地 | 工場現場（油汚れ・騒音のある環境） |
| 技術スキル | スマホ入力は得意だが、PCでの長文レポート作成は苦手で嫌い。複雑なOracle DBへの入力が苦痛 |

## 目標・ゴール

- **責任の正当な評価**: AIの客観的判定により「これは設計の責任です」と証明し、自部門への不当なコスト負担を減らしたい
- **瞬時の解決**: トラブル入力時に「この部品を変えれば直る」と過去の知見をRAGで即座に提示してほしい
- **入力の最小化**: 油まみれの手でも、最小限の操作でトラブル報告を完了させたい

## 課題

- **徒労感と冤罪**: 明らかに部品の強度不足（設計ミス）なのに、「現場のメンテナンス不足」「使い方が乱暴」と責められる。報告書を書いても設計は改善されず、同じトラブルが繰り返される
- **入力の負担**: 油まみれの現場環境で、複雑なシステムへの入力を求められる。「直しました」と一行書くのが限界
- **製造部門の経費圧迫**: 設計起因のトラブルの修繕費が製造部門に計上され、部門の評価が下がる

## 利用状況

| 利用場面 | 頻度 | 詳細 |
|---------|------|------|
| トラブル発生時の報告入力 | 日次（複数回） | 現場でスマホまたはタブレットから最小限の情報を入力。AIが構造化を補助 |
| 過去事例の検索（RAG） | トラブル発生時 | 入力中にRAGが類似トラブルの解決策を自動提示。復旧時間の短縮を期待 |
| AI原因判定の確認 | 報告後 | AIが「設計起因」と判定した結果を確認し、自部門の正当性の根拠として利用 |
